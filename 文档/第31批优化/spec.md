# 第 31 批优化：缺标准库 jar 的诊断直达

## 1. 目标

学习者写了 `导入 中文.标准库.*;`，但用 `cjc 编译` 手动编译（没加 `-cp`），或仓库还没构建出标准库 jar 时，改前只会看到「包「中文.标准库」不存在」加一句通用的“检查包名拼写”；第二条诊断还会让用户补一行已经写好的导入。改后第一条直接说明「标准库 jar 不在类路径」，并给出构建与手动编译两条可照做的做法。

## 2. 现状（改前实测）

`构建\第31批\改前\显示.java`：

```java
导入 中文.标准库.*;

类 显示 {
    入口 {
        输出.打印行("你好");
    }
}
```

`.\cjc.ps1 编译 构建\第31批\改前 -d 构建\第31批\改前\out` 输出：

```
错误：第1行 第6列  包「中文.标准库」不存在
    建议：检查包名拼写与目录结构；Maven 工程需要先加依赖。

错误：第5行 第9列  找不到符号：标准库类「输出」
    建议：在文件开头加一行「导入 中文.标准库.*;」；只用一个类时可写「导入 中文.标准库.输出;」。用 运行.ps1 会自动带上标准库 jar。
```

问题：

1. 包名没有拼错，通用建议把用户引向错误方向。
2. 第二条让用户补导入，可导入明明已经写了，真实原因是 jar 不在类路径。

## 3. 变更

### 3.1 `工具\cjc\Cjc.java`

- `localizeJavacMessage` 新增一条无法表驱动的特例：包名以 `中文.标准库` 开头且报“包不存在”时，走 `stdlibPackageRule`。
  - 同时匹配英文 `package X does not exist` 与中文 `程序包X不存在`（本机 JDK 即使请求英文 locale 也返回中文原文）。
- 新增 `stdlibPackageRule(String pkg)`，消息为「包「X」不存在：标准库 jar 不在类路径」，建议为：
  「先在仓库根目录执行「mvn -f 标准库\pom.xml package」；手动编译时用「-cp」指向 标准库\target 下的 cjc-stdlib-*.jar，或用 运行.ps1 自动带上 jar。」
- `stdlibImportHint`（第 30 批新增）补一句：已经写了导入仍报错时，说明 jar 不在类路径，并给出 `mvn package` 与 `运行.ps1`。
- 更新方法注释：特例由 4 条改为 5 条。

### 3.2 `工具\发布\校验.ps1`

- 诊断反例新增「14缺标准库jar」：源码含 `导入 中文.标准库.*;`，用 `cjc 编译`（不带 `-cp`）执行，断言退出码 1、输出含「标准库 jar 不在类路径」与「标准库\pom.xml」。
- 通过提示改为「13 条 + 缺标准库 jar 提示全部命中中文输出」。

### 3.3 文档同步

- `语言规范.md` 第 7.1 节 javac 错误对照表：新增 `package … does not exist / 程序包…不存在` 一行，说明标准库包会给出 jar 与 `-cp` 做法。
- `教程\教程.md` 第 6 节「常见错误」：新增 `包「中文.标准库」不存在` 一行。
- `速查表.md` 第 8 节末：补一句“写了导入仍报该错误说明 jar 不在类路径”。
- `工具\cjc\诊断中文表.txt` 表头注释补「标准库包不在类路径」特例。
- 新增本目录 `spec.md` / `tasks.md`。
- 不升版本、不改 `CHANGELOG.md`（延续第 10–30 批做法）。

## 6. 风险

- 只影响包名以 `中文.标准库` 开头的“包不存在”诊断；其他包（如反例 10 的 `别处.不存在`）仍走通用建议，可回归验证。
- 英文与中文两套 javac 文案都在特例里处理，不依赖 JDK 语言包。
