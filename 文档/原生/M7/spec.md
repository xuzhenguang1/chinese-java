## 目标

| 序号 | 目标 | 验收 |
| --- | --- | --- |
| 1 | 原生优先工程脚手架 | `新建 项目` 后 `.\构建.ps1` 产出可运行 exe |

## 设计

### 1. 顶层 `包` 声明

```java
// 语法分析器.解析()
if (是关键字("package")) {
    解析包声明();   // 消费 `包 名称(.名称)*;`，不建 AST 节点
}
```

- `解析包声明` 只调用 `取 / 期望名称 / 期望符号`，丢弃名称。
- 不改 `编译单元`、`语法树打印器`、语义分析与后端；AST 快照零差异。
- 入口识别仍以 `入口` 方法为准，与包名无关。

### 2. JSON 诊断协议

命令：

```
原生\驱动.ps1 诊断 [--json] <文件或目录...>
```

`--json` 时 stdout 每行一个对象，不混入其它文本：

```json
{"码":"CJK001","行":4,"列":5,"长度":2,"消息":"…","建议":"…","错误":true}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 码 | 字符串 | CJK001 / CJK002 / CJK106 / CJK101–105 / 语法 / 非法字符 |
| 行 / 列 | 整数 | 1 起始，与 `诊断.项` 一致 |
| 长度 | 整数 | 下划线宽度；词法层记录真实宽度，其余为 1 |
| 消息 / 建议 | 字符串 | 中文诊断与修复建议 |
| 错误 | 布尔 | true 映射 Error，false 映射 Warning |

退出码：成功输出诊断（含错误诊断）= 0；读文件失败或内部异常 = 2。
`--json` 时前端编译日志被抑制，失败信息走 stderr。

### 3. VSCode 接入

- 配置 `cjc.diagnosticSource`：`原生`（默认）/ `兼容`。
- `构建\原生\前端\classes` 存在时直接 `java -cp <classes> 前端主程序 诊断 <root> <file> --json`；
  否则用 `powershell -File cjc.ps1 原生 诊断 --json <file>`（会先编译前端）。
- 解析失败或退出码非 0 → 提示一次并回退 `Cjc.java` 链路。
- Quick Fix 逻辑保持原样：CJK001 补空格、CJK002 改半角、CJK106 折叠标点等。
- 补全数据 `补全数据.json` 由 `同步词表.ps1` 生成。

### 4. 增量编译

```
构建\原生\缓存\
  运行时\<名>-<内容哈希8>.o
  模块\<模块>-<C或IR内容哈希8>.o
  状态\<模块>.json          # 源哈希 / 运行时哈希 / 工具链哈希 / 输出 / 时间
```

- 跳过条件：四项全部匹配且 exe 存在。
- 模块对象复用按 C/IR 内容哈希；运行时对象按源码内容哈希。
- 编译旗标固定；`-无缓存` 走原一次性 `clang` 路径用于对照。
- 任何缓存读取异常按未命中处理。

### 5. 工程脚手架

```
我的工具\
  pom.xml                  # JVM：mvn package -> target\cjc-app-1.0.jar
  构建.ps1                 # 原生：.\构建.ps1 -> target\应用.exe
  src\main\中文\演示\应用\主程序.java
```

`构建.ps1` 用生成时的仓库相对路径定位 `cjc.ps1`；跨盘符时写绝对路径；
脚本带 UTF-8 BOM，避免 Windows PowerShell 5.1 按 ANSI 读取导致中文乱码。

## 兼容性

- C 后端仍是默认后端；LLVM 后端仍可用。
- `原生 检查`、`语法树`、`对拍`、`中间` 等既有子命令行为不变。
- 旧 VSCode 链路保留，配置切回 `兼容` 即恢复。
