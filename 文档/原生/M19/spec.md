# M19 符号冲突根治 · 规格说明（spec）

> 对应 `tasks.md` / `checklist.md` / `对拍报告.md`。决策来源：`文档/原生/后续路线计划书-M19至M22.md` §3 与 §7.1（2026-11-23 已拍板）。
> ADR：`文档/原生/ADR/ADR-022-M19符号冲突根治.md`（Accepted）。
> 定位：清偿 M13 spec 标记的技术债「根本解决另立里程碑」——让类名/类型引用在 MIR 与后端符号里携带包名，从地基上消除跨包同名类符号冲突。

## 1. 目标与非目标

### 1.1 目标

- **G1 全限定名进符号（根治）**：顶层类在 MIR 里编码为 `包名$类名`，类型引用（字段/方法参数/返回/静态字段/异常/继承）统一使用带包全名；后端 `编码()` 对该全名逐码点 hex 串烧成 C/LLVM 符号，使两个不同包的同名类产出不同符号。
- **G2 旧简单名别名过渡**：C 后端注入 `#define` 旧符号别名、LLVM 后端注入 `alias`，使过渡期引用旧简单名符号的代码不断裂；范围与清理时机（M22 收官）写进 ADR-022。
- **G3 端到端策略不变**：保留「模块内简单类名唯一」中文诊断，端到端仍禁止同名类；M19 只修符号地基能力，不解锁该约束。
- **双轨验收**：能力层用后端层单测证明 G1 根治（绕过诊断层），策略层证明 G2 别名可用 + G3 诊断仍拦下 + 快照零回退。

### 1.2 非目标

- 不解除 G3 的简单类名唯一诊断（端到端同名类仍被拦下）。
- 不改后端 `编码()` 算法本身（M19 后冻结，M20–M22 不得改）；只在符号名来源（类名是否已带包）与新符号生成上改动。
- 不改 JVM/C/LLVM 对拍的可观察行为（G3 保证端到端输入输出零回退）。
- 不在 M19 清理旧别名（推迟到 M22 收官）。

## 2. 决策（G1–G3，2026-11-23 拍板）

| 编号 | 决策 | 落地 |
| --- | --- | --- |
| G1 | 采用方案 A：语义层拼包名，全限定类名进 MIR；`包名$类名` 结构，逐码点 hex 编码 | 参考侧 `语义分析器.java` + 自举侧 `自举前端.java` 对称改造；后端符号自动区分 |
| G2 | 保留旧简单名别名作为过渡（M22 清理） | C `#define M19 旧符号别名`、LLVM `alias ... ; M19 旧符号别名` |
| G3 | 保留「模块内简单类名唯一」诊断，端到端仍禁止同名类 | 反例 01 逐字节零回退 |

**G2×G3 张力处置**：G3 使端到端无同名类用例，故 G1 根治能力**只能**由后端层单测证明（绕过诊断层直接构造两包同名类 MIR）。这是 M19 能力层的唯一实证，缺此则 M19 退化为「改了编码却无法验证」。

## 3. 方案 A 全量改造面

### 3.1 参考侧 `原生/中间表示/src/中文/原生/中间/语义分析器.java`

- 新增 `当前包名`、`简单名到全名` 索引；`收集()` / `收集声明()` 设置当前包名；`预扫描顶层类名(单元们)` 在 pass1 前建立索引。
- `收集类`：顶层类编码为 `当前包名.isEmpty() ? 名 : 当前包名 + "$" + 名`，并登记简单名映射。
- `查找类名(String)` 支持简单名→全名；`转类型` 用规范化全名；`校验导入`、`检查类型名` 使用索引。
- 时序修正：`查找类名` / `转类型` 直接信任预扫描索引构造规范全名，不要求 `类表.containsKey(全名)`（pass1 顺序未到也能解析引用）。

### 3.2 自举侧 `原生/自举/自举前端.java`（与参考侧对称）

- `编译单元节点` 加 `包名` 字段；`解析()` 保存 `解析包声明()` 返回值（分两步，避免链式调用触发语法问题；局部变量名用 `包名前缀` 避开关键字 `包`）。
- `语义检查器` 加 `当前包名`、`简单名到全名`；`收集(单元)` / `准备模块()` 设置包名并预扫描。
- `收集类` 拼 `包名$类名`；`查找类名` 索引末段匹配；`校验导入模块` 用索引；`收集速览` 加包名参数，参考侧 `前端主程序.java` 同步。

### 3.3 后端别名（G2）

- `C生成器.声明结构体()`：为带包类注入 `#define <旧符号> <新符号> /* M19 旧符号别名 */`。
- `LLVM生成器.生成描述符()`：注入 `@<旧符号> = alias %cjk_class, ptr @<新符号> ; M19 旧符号别名`。
- `旧简单名(String)` 仅当类名含 `.` 才生成别名，避免无包嵌套类（如 `$学生`）误生成。

## 4. 验收口径

1. **能力层**：`后端同名类测试.java` 绕过诊断层，构造 `演示.甲$工具` / `演示.乙$工具`，断言 C/LLVM 双后端全名 hex 符号存在、不同、含各自包名编码、覆盖多符号位置（10/10）。
2. **策略层**：反例 01「重复类名」端到端仍被中文诊断拦下（零回退）；旧别名在两后端源码注入点就位。
3. **零回退**：35 课四路对拍、105 份快照、自举不动点 3/3、示例工程与 M18 专用样例三方对拍全绿。
4. **基线迁移**：`自举前端.M18.mir.txt` 冻结旧基线（SHA `3324cb5a...`），阶段2 重生成基线 `a4554405...` 冻结为 `自举前端.M19.mir.txt`，最终 `自举前端.mir.txt` SHA `f8e5516b...`（阶段4 修正诊断类名带包后重生成），A/B 双实现交叉确认；`自举前端.历史.mir.txt` 保留更早历史（M18 前）。
5. **硬门槛**：`校验.ps1 -含原生` 新增 8.18 后退出码 0，ADR 总数 22。
