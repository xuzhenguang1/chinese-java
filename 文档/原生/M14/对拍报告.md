# M14 Linux ELF 对拍报告

> 实测日期：2026-11-21。口径：用户 2026-11-20 三项决策——一步到位可运行 ELF / musl + qemu / 文件 IO 与 socket 网络全做。
> 所有数值来自本机真实命令输出；构建中间产物在 `构建/` 下，不提交。

## 1. 运行环境

- 宿主：Windows（win32），Git Bash + PowerShell 5.1。
- 交叉工具链：本机 clang（MSYS2 mingw64）`--target=x86_64-linux-musl` + ld.lld；musl sysroot 来自 Alpine CDN `musl-dev-1.2.5-r4.apk`（解压到 `构建/工具链/alpine/sysroot/`）。
- ELF 运行器：`qemu-system-x86_64` 11.1.0 + Alpine v3.20 `linux-virt` 内核 + 自建 newc initramfs（串口 `ttyS0` 捕获输出，跑完 `poweroff -f` 自动关机）。
- qemu 打不开中文路径，统一经 ASCII junction `E:\cjk-qemu`、`E:\cjk-alpine` 访问。
- musl 把 pthread/clock 并入 libc，`libm.a`/`libpthread.a` 均为空归档，链接只需 `-lc`。

## 2. 统一运行器（T6.1）

- `原生/测试/运行器.ps1`：Windows 模式用 `Start-Process` 跑 exe；Linux 模式接收若干 ELF，一次打包 initramfs → 启动 VM → 解析 `===CJK_CASE:` / `===CJK_EXIT:` 标记 → 写回 `<名>.elf.out` / `<名>.elf.exit`。
- `原生/测试/工具/运行VM.py`：用 `subprocess.run` 启动 qemu（绕开 PowerShell 的进程启动安全限制），字节级保留输出。
- `原生/测试/工具/构建initramfs.py`：newc cpio 打包器；新增可选 `CJK_INIT_PRE` 环境变量注入 init 前置脚本（网络冒烟起本地 HTTP 服务用），默认空，既有调用零影响。
- 批量效率：35 个 ELF 一次 VM 运行约 5 秒（含自动关机）。

## 5. GC 压力（T6.4）

- `原生/测试/GC压力Linux.ps1`：复用 M12 四组中文用例，编译 ELF 后批量 VM 运行，断言退出码 0 + 输出子串。
- 结果：**4 / 4 通过**：对象分配 `合计：45002138890`、字符串 churn `串长：7`、集合增删 `终值：1000`、深层对象图 `链长：2000`。
- VM 内无法采样 Windows 工作集，故不做内存峰值断言；M12 的 Windows 侧工作集断言保持不动。

## 6. 网络冒烟（T4.2 / T6.4）

- `原生/测试/网络冒烟Linux.ps1` + 夹具 `原生/测试/网络探针.java`：VM 内 `ip link set lo up` + busybox `nc -l -p 80` 起本地 HTTP 服务，ELF 经 `网络.取文本()`（socket/getaddrinfo/connect/send/recv）GET `http://127.0.0.1/hello`。
- 结果：**通过**。ELF 输出 `正文：你好，网络`，退出码 0，中文 UTF-8 正文真实往返。
- 实测中发现并修复一处真实 bug：Linux `网络失败()` 用 `缓冲追加ASCII` 追加中文原因字面量导致异常消息乱码（显示为 `æ æ³•`），改为 `cjk_str_from_utf8` + `缓冲追加文本` 后正确显示 `无法连接主机：...`。Windows 分支未改动。

## 7. 异常栈一致性

- 第20/21课（异常捕获）在 ELF 侧 C/LLVM 两后端输出逐字节一致，中文类名、消息、源行号正确（T5 首通已验证，T6 全量对拍覆盖）。
- 未捕获异常的中文栈（如网络失败）经上述 bug 修复后 UTF-8 正常。

## 8. 平台抽象与 Windows 零回退

- 驱动 `-平台 linux` 参数化、缓存分桶、LLVM 平台配置对象均为增量改动；Windows 默认配置的 IR 关键行（datalayout/triple/handler `[32 x i64]` / `_setjmp` 双参 / frameaddress / align 16）与 M0–M13 一致。
- Windows 全量校验（`校验.ps1 -含原生`）退出码 0，证明 M14 改动对 Windows PE 零回退。
