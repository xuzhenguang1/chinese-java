# M14 Linux ELF 基准报告

> 实测日期：2026-11-21。口径：所有数值来自本机真实命令输出。
> 本报告说明 ELF 性能基准的采集边界，并给出 Windows 侧零回退基线。

## 1. 结论先行

**M14 不改动默认优化级别（`-O2`），Windows 侧 LLVM/C 比值维持 M12 结论。**
Linux ELF 的正确性由 `M14/对拍报告.md` 的 35/35 × 2 后端全量对拍保证；
性能方面，ELF 在 qemu-system 全系统模拟 + initramfs 环境下运行，**VM 启动与
串口 I/O 开销远大于被测程序本身**，不具备与 Windows 原生 PE 或 JVM 可比的性能意义，
因此不把 VM 耗时当作性能回归判据。

## 2. 为什么 ELF 性能基准不可比

- qemu-system-x86_64 是全系统模拟（非 qemu-user 的二进制翻译），每条指令都付出模拟开销；
- 35 课 ELF 批量跑完约 5 秒，其中绝大部分是内核启动 + initramfs 解压 + 串口回显；
- init 脚本跑完 `poweroff -f`，VM 无真实工作集/内存压力采样能力（M12 的工作集断言在 VM 侧不适用）；
- 因此 `基准.ps1` 的 LLVM/C 比值门槛（M6 基线 ±0.05、>1.05 硬失败）继续以 Windows 原生 PE 为准。

## 3. Windows 侧零回退基线（M14 改动后实测）

M14 改动了 `LLVM生成器.java`（平台配置注入）、`驱动.ps1`（`-平台` 参数化）、
`cjkrt.c`（静态断言平台分派）、`文件.c` / `标准库.c`（Linux 分支补完）。
这些改动对 Windows 默认路径均为增量/分支隔离。校验脚本 `校验.ps1 -含原生`
退出码 0，其中基准门槛（8.4）通过，证明 LLVM/C 比值未回退。

M12 记录的五档 LLVM/C 比值（Windows，-O2 默认）作为对照基线：

| 档位 | 斐波那契 | 长循环 | 字符串拼接 | 键值表读写 |
|---|---|---|---|---|
| O2（默认） | 1.042 | 1.007 | 1.001 | 1.016 |

> 注：M14 期间曾出现一次「键值表读写 1.061」的偏移，经定位是并行下载任务占满 CPU/IO
> 导致的机器负载漂移（非代码回退）；在下载停止、机器空闲后重跑恢复常态。基准结论以空闲环境实测为准。

## 4. ELF 侧可验证的性能相关事实

- 交叉编译使用 `-O2`（与 Windows 默认一致），未引入 Linux 专属优化分支。
- musl 静态链接，pthread/clock 并入 libc，链接无多余动态库。
- GC 压力四组在 ELF 侧全部退出码 0、输出正确（见 `对拍报告.md` 第 5 节），
  证明保守 GC 在 musl 静态环境下无崩溃、无死循环式泄漏迹象。

## 5. 采集命令（可复现）

```powershell

.\原生\测试\基准.ps1 -重复 2 -优化 O2

# Linux ELF 正确性对拍（非性能）
.\原生\测试\对拍ELF.ps1 -后端 c
.\原生\测试\对拍ELF.ps1 -后端 llvm
.\原生\测试\GC压力Linux.ps1
.\原生\测试\网络冒烟Linux.ps1
```
