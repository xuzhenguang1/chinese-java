# M13 平台配置说明与 Linux 静态检查报告

> A4 产出。本里程碑仍只产出 Windows PE，默认值全部保持 PE/Win64 不变。
> 本文把散落在驱动与 LLVM 生成器里的平台相关参数**集中记录**于一处，作为 M14 交叉工具链的输入清单。

## 1. 平台相关参数清单（当前值 = Windows PE/Win64，行为不变）

| 参数 | 当前值 | 位置 | M14 交叉编译时需替换 |
| --- | --- | --- | --- |
| clang 探测 | `C:\msys64\mingw64\bin\clang.exe`（回退 PATH） | `原生/驱动.ps1:58-69` 查找clang | 增加 `x86_64-linux-gnu-clang` 候选 |
| 运行时编译参数 | `-c -O2 -std=c11 -fwrapv -fno-strict-aliasing -I 原生/运行时` | `驱动.ps1:176`、`:523`、`:545` | 追加 `--target=x86_64-linux-gnu --sysroot=<路径>` |
| 链接参数 | `-static <objs> -lm -lwinhttp -lws2_32 -lshell32` | `驱动.ps1:203` 链接可执行 | 换 `-lm -lpthread`，去 winhttp/ws2_32/shell32 |
| LLVM 系统行 | `x86_64-w64-windows-gnu` | `LLVM生成器.java:46` 系统行 | `x86_64-linux-gnu`（需加 `-fPIC`/动态链接策略） |
| LLVM datalayout | `e-m:w-p270:32:32-p271:32:32-p272:64:64...`（Win64） | `LLVM生成器.java:184` | `e-m:e-p270:32:32-p271:32:32-p272:64:64...`（ELF） |
| jmp_buf 布局 | `[32 x i64]`（MinGW Win64） | `LLVM生成器.java:236` | 随 Linux libc jmp_buf 调整 |
| _setjmp 签名 | `i32 @_setjmp(ptr, ptr)` 两参（MinGW） | `LLVM生成器.java:1215、:1238` | glibc 单参 `setjmp`，需重做异常展开 |
| jmp_buf guard | `_Static_assert(sizeof(jmp_buf)==256)` | `cjkrt.c:98-104` | Win64 保留；Linux 按目标 libc 重写 |

以上参数全部保留现状；M13 只做集中归档，不改任何一处的默认值。

## 2. Linux `-fsyntax-only` 静态检查结果（M14 工具链前置输入）

- 命令：`clang --target=x86_64-linux-gnu -fsyntax-only -std=c11 -I 原生/运行时 <file>.c`
- 执行时间：2026-11-20；clang 23.1.5（MSYS2 MinGW 版，宿主 target `x86_64-w64-windows-gnu`）
- 结果：**全部 8 个运行时 .c 均在预处理阶段因缺 Linux 标准头终止**（预期内，见 ADR-017"本机不产可运行 ELF"）。

| 源文件 | 首个缺失头 |
| --- | --- |
| `cjk_platform.c` | `wchar.h` |
| `gc.c` | `setjmp.h` |
| `cjkrt.c` | `setjmp.h` |
| `值.c` | `setjmp.h` |
| `文件.c` | `setjmp.h` |
| `标准库.c` | `setjmp.h` |
| `文本.c` | `setjmp.h` |
| `集合.c` | `setjmp.h` |

**根因**：`C:\msys64` 只有 MinGW-w64 一套 CRT，无 `x86_64-linux-gnu` 的 sysroot/libc/crt1.o；WSL 被安全策略禁用（M3 已记录 `wsl --status` 退出码 50）。缺的不是某个头文件而是整个标准库头文件树。

**M14 前置条件**：安装 `mingw-w64-x86_64-clang` 之外的 Linux sysroot（如 `msys2 mingw-w64-x86_64-gcc-libs` 不适用；需 `x86_64-linux-gnu` 交叉 sysroot 或启用 WSL），再重跑本表，逐个补齐平台分支的类型/函数实现。

## 3. 平台抽象六类接口落点（本里程碑已完成）

| 接口类别 | 声明 | Windows 实现 | Linux 实现 |
| --- | --- | --- | --- |
| 锁/once/原子 | `cjk_platform.h` | `CRITICAL_SECTION`/`INIT_ONCE`/`Interlocked*` 宏直映 | pthread mutex/once + `__atomic_*` |
| 线程栈顶 | `cjk_thread_stack_top()` | TEB `__readgsqword(0x08)` | `pthread_getattr_np` 栈上界（非 NULL） |
| 墙上时钟 ms | `cjk_wall_millis()` | `GetSystemTimeAsFileTime` | `clock_gettime(CLOCK_REALTIME)` |
| 控制台 UTF-8 | `cjk_console_init_utf8()` | `SetConsole{Output,}CP(CP_UTF8)` | 空操作（终端默认 UTF-8） |
| 命令行参数 | `cjk_platform_program_args()` | `CommandLineToArgvW` + UTF-8 转换（值.c 样板原样迁入） | argv UTF-8 字节 |
| 路径分隔符 | `CJK_PATH_SEP[_W]` | `'\\'` | `'/'` |

文件 IO（`文件.c` 全文）与网络 IO（`标准库.c` WinHTTP 段）按 `CJK_PLATFORM_WINDOWS` 分区：Windows 分支原样保留，Linux 分支返回明确中文诊断。
