# M13 规格（平台抽象层 · 多文件模块 · 地基双雄）

> 状态：已实施（2026-11-20，ADR-017 Accepted）。方向来自用户 2026-11-20 决策（选项 1+2 一起安排）：把「平台抽象层」与「多文件模块」作为 M13 一起做，先出方案、评审通过再开工。
> 编号说明：既有文档（M12 spec:32、ADR-010、`.trae/...M11 实施计划`）把 ELF/包管理/多文件分别写作 M13/M14/M15。本里程碑以 ADR-017 正式重排：原 M13 ELF 顺延为 M14（需先有平台抽象），原 M14 包管理顺延为 M15（需先有多文件），两块地基合并为 M13。路线图正文补 M13 小节。

## 目标

解除后续跨平台（ELF）与包管理的两个前置依赖，同时**不触碰**已锁定的 35 课对拍、三类快照、自举不动点与全量校验口径：

- **平台抽象层**：把运行时对 Windows API 的裸露依赖收口到统一接口，Windows 后端行为逐字节不变，Linux 后端具备可编译骨架（本机不做可运行验收，见"不在范围"）。
- **多文件模块**：让 `包` 声明进入 AST、建立跨文件共享类表与模块编译单元，使 `示例工程`（3 包 11 文件）能一次编译为一个 exe。

## 编号与依赖（为什么要先做这两块）

| 既有编号 | 内容 | 前置依赖 | 重排后 |
| --- | --- | --- | --- |

### 单文件假设面

- `包`/`导入` 已是关键字（`关键字表.txt:24-25`），词法器数据驱动识别；`从` 不存在（语义为内建助手，不动）。
- `解析包声明()`（`语法分析器.java:76-85`）只消费标记不建节点；`编译单元` record 无包字段（`语法树.java:27`）。ADR-010 当初为保快照零差异的取舍。
- 语义分析器 `类表` 是**实例字段**（`语义分析器.java:166`），每文件 new 一个（`前端主程序.java:657`），跨文件类型完全不可见；`转类型()` 有"未知类型放行"兜底（:3044），但使用处仍报 `未知类`。
- MIR `程序` 只持一个 `位置信息(源路径)`（`中间代码.java:12-27`）；解释器扫单个程序的 `<入口>`。
- C/LLVM 符号编码 `编码()` 只用简单类名（`C生成器.java:2349-2360`、`LLVM生成器.java:3271`），合并翻译单元后同名类会撞符号。
- 驱动 `编译` 只取第 1 个源文件（`驱动.ps1:458`），缓存键只哈希单文件（:491）。
- **可复用验收样例**：`示例工程/` 已有 3 包 11 文件结构（`包 演示.应用;` + 4 条跨文件 `导入`），是天然的多文件对拍目标。

## 范围

### 子项 A：平台抽象层（行为保持重构 + 可插拔骨架）

- A1 新建 `原生/运行时/cjk_platform.h`：收口六类接口——锁/once/原子、栈上界、单调时钟、控制台初始化、命令行参数、目录分隔/路径样式。以 `值.c:373-398` 的 `#ifdef/#else` 为样板。
- A2 把 `gc.c`、`标准库.c`、`文件.c`、`cjkrt.c` 的裸露调用迁到接口；**Windows 后端逐字节复用现有实现**（不改行为），Linux 分支给可编译实现或明确桩。
- A3 网络（WinHTTP 745-924）与文件 IO（`文件.c` 全文）第一步做**可桩化隔离**（Linux 分支返回明确中文诊断，不静默），不追求首轮跑通文件/网络对拍。
- A4 驱动与 LLVM 生成器的目标相关参数集中为"平台配置"一处可读开关（本里程碑仍只产出 PE，不改默认值）。

### 子项 B：多文件模块（两阶段共享类表 + 模块编译单元）

- B1 `包` 声明建 AST 节点 `包声明(String 名称)`，`编译单元` 增包字段；打印器"有包才打印、无包零新增行"以保 35 课快照。
- B2 语义分析器提供"模块入口"：第一阶段扫描全部源文件、注册类名/继承关系到**共享类表**（只注册一次内建类），第二阶段逐文件分析方法体，产出一个合并的 `中间代码.程序`，显式指定唯一 `<入口>` 所在文件。
- B3 新增模块编译子命令：前端接收多个源文件 → 一个共享分析 → 一个 C/IR 输出；驱动 `编译` 接受 `<源文件...>`，缓存键改聚合哈希。
- B4 导入先做**校验/诊断**（目标类是否在模块内），Java 侧 `导入 java.util.*` 忽略；模块成员资格由文件列表决定，不实现的 classpath 推导。
- B5 C/LLVM 符号冲突：MVP 采用"模块内简单类名唯一性诊断"（重复类名给中文错误），不改 `编码()` 以免波及快照与不动点。

## 不在范围（硬边界）

- **本机不产、不验收可运行 Linux ELF**：`C:\msys64` 仅有 MinGW-w64 一套 CRT，无 `x86_64-linux-gnu` sysroot/libc/crt1.o，`ld.lld` 虽在但链不出可运行 ELF；WSL 被安全策略禁用（M3 已记录 `wsl --status` 退出码 50）。Linux 分支只做**可编译骨架 + 静态检查**，运行验收待引入工具链（顺延 M14）。
- 不实现包管理/依赖解析/远程仓库（顺延 M15）。
- 不改 35 课任何源文件、三类快照（AST/语义/MIR）、自举不动点断言、DWARF 与基准口径。
- 不改 `自举前端.java`、不改 C/LLVM `编码()` 符号规则（改则 `自举前端.mir.txt` 与不动点连锁失效）。
- 不引入第三方 GC、不换异常展开机制（setjmp/longjmp 保持）。
- 不改 `导入` 的 JVM 语义；`从` 不新增为关键字（会动词表计数断言）。
- 不改 `校验.ps1` 现有 35 课断言，只新增 M13 断言。

## 关键口径

### A：平台抽象的可验收落点

本机无 Linux 运行环境，故平台抽象层的验收锚定在"Windows 行为零回退 + Linux 骨架可静态检查"两条：

1. **行为保持**：Windows 后端下 `校验.ps1 -含原生` 全过（退出码 0），35 课 C/LLVM 对拍 35/35，异常栈逐字节一致，GC 压力、基准门槛不回退。
2. **骨架可检查**：`cjk_platform.h` 的每个 Linux 分支提供完整声明；用 `clang --target=x86_64-linux-gnu -fsyntax-only`（不链接）对 7 个 .c 做语法/类型检查，允许因缺系统头失败但需记录具体缺失清单，作为 M14 工具链前置的输入。

### B：多文件模块的可验收落点

以 `示例工程/` 为对拍目标：JVM 后端（`javac` + `java`）与原生模块编译（一次编 11 文件为一个 exe）stdout/退出码逐字节一致。AST 打印新增 `包 演示.应用` 行由**新快照**锁定，旧 35 课快照零变化。

## 验收清单（摘要，详见 checklist.md）

- `.\工具\发布\校验.ps1 -含原生` 退出码 0（全量回归，含新增 M13 断言）。

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 平台抽象重构破坏 Windows 行为 | 35 课对拍/快照回退 | Windows 后端逐字节复用现有代码，逐子项跑全量校验；纯搬运不改语义 |
| Linux 分支无法本机运行验收 | 交付"看起来对"的幻觉 | 明确不在范围，只做静态检查并归档缺失清单；可运行性作为 M14 硬门槛 |
| `编译单元` 增字段破坏 record 兼容性 | 编译失败 | 加规范构造器重载兼容旧 3 参调用；全仓构造点仅 1 处（`语法分析器.java:66`）已核实 |
| 多文件合并后 C 符号冲突 | clang 重定义错误 | MVP 强制模块内简单类名唯一 + 中文诊断；根本解决（包名进编码）另立里程碑 |

| 缓存键只哈希单文件 | 改被引用文件仍复用旧 exe | 聚合哈希全部源文件 + 运行时 + 工具链 |
| 不动点连锁失效 | M8–M11 断言崩 | 不改自举前端与 `编码()`；新增快照与旧快照物理隔离 |
