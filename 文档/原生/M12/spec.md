# M12 性能与内存 规格（影子栈 · GC 加固 · 基准门槛 · 优化调优）

> 状态：方案待评审。里程碑方向来自 `.trae/documents/M11-自举五期-泛型与自举自举-实施计划.md` 第 7 节；
> 路线图正文第 7 节只到 M11，故本 spec 是 M12 的详细设计，评审通过后再开工。

## 目标

在不改变 35 课对拍口径、不破坏自举不动点的前提下，补上原生后端的两块运行时可观测能力
（逐帧中文异常栈、内存压力可验证），并把性能验收从"相对比值"升级为"回归门槛 + 多后端基线"。

## 范围

- 子项 1：影子栈与逐帧中文异常栈（C 后端 + LLVM 后端双实现）。
- 子项 2：GC 加固与独立压力脚本（多线程暂停回收策略显式化、根覆盖核查、压力用例脚本化）。
- 子项 3：基准回归门槛（固化 M6 记录值 + JVM/原生多后端基线对比）。
- 子项 4：优化级别验证与调优接口（-O2 现状确认、可选 LTO/-march 实测、基准报告）。

## 不在范围

- 不改 MIR、前端、自举前端、词表、35 课任何源文件语义。
- 不引入 Boehm / 第三方 GC 依赖（ADR-006 已定自研）。
- 不实现真正的栈展开（DWARF unwind）；影子栈是显式维护的调用帧链，异常路径仍用 setjmp/longjmp。
- 不承诺 Linux ELF（M13）/ 多文件模块（M15）/ 包管理（M14）。
- 不改异常捕获的语义与输出首行格式（校验.ps1:869-899 的断言必须继续通过）。
- 不做新的语言特性；并发/网络等标准库行为不变。

## 关键口径

### 子项 1：影子栈（新增）

**目标**：未捕获异常和栈回溯能打印逐帧中文调用栈，形如：

```
未捕获异常：数组越界异常：Index 5 out of bounds for length 3
  于 类.方法(教程\第20课.java:12)
  于 类.调用者(教程\第20课.java:20)
  于 类.入口(教程\第20课.java:25)
```

**数据结构**（放在 `cjkrt.h`，布局需 LLVM 后端同步）：

- `cjk_frame { const char *方法名; int32_t 行号; cjk_frame *上一帧; }`；
- 全局 `cjk_frame *cjk_frame_top`；
- 接口：`cjk_frame_push(名, 行)` / `cjk_frame_pop()` / `cjk_frame_set_line(行)` / `cjk_frame_print(FILE*)`。
- 帧内容用**静态字符串常量**（类名 C 名 + 中文方法名，UTF-8，生成期写死），不分配堆内存，避免 GC 交互。

**埋点位置**：

- C 后端 `C生成器.生成方法`（`:662`）方法体开头 emit `cjk_frame_push(...)`，函数返回前 emit `cjk_frame_pop()`；
- LLVM 后端 `LLVM生成器` 对应方法入口/出口 emit 同样调用（用 `%cjk_frame` 结构 + 全局指针）；
- `生成尝试`/`尝试语句`（C `:800` / LLVM `:1162`）在 `setjmp` 前记录当前帧深，在 catch 分支恢复帧深（longjmp 会跳过正常 pop）；
- 行号：方法入口 push 定义行（类/方法声明），调用点用 `cjk_frame_set_line(当前行)` 更新为调用行；未捕获时由 `cjk_throw` 的 `line` 参数定位抛出点。

**风险与坑**：

- longjmp 跳过栈帧 pop 是头号隐患：必须在 handler 里保存/恢复帧深，否则二次异常栈错乱。
- 影子栈帧数与递归深度成正比，深度递归（基准 fib(28)）会累积；需设上限（如 1024 帧）并做截断提示。
- 静态字符串常量含中文，UTF-8 输出必须走现有 `写码点` 路径（不要 `fprintf("%s")` 直接吐 C 源码字节，Windows 控制台已 CP_UTF8，但重定向到文件时需保证字节正确）。
- LLVM 后端 `cjk_frame` 布局/全局声明需与 C 运行时一致，按 M6 惯例加 `_Static_assert`。

### 子项 2：GC 加固

**目标**：修正已知弱点、把压力用例从校验脚本内联（`:905-959`）抽成独立可复跑脚本，并让文档口径与实现一致。

**动作**：

- 保留自研保守标记-清除与 TEB.StackBase 根扫描（已验证，不动算法核心）。
- 多线程：显式化"存活线程 >1 暂停自动回收"策略——在 `cjkrt.h:92-94` 注释的基础上，补一条中文可观测提示或诊断开关（`cjk_gc_pause_auto` 状态查询），避免静默。
- 根登记覆盖核查：确认静态字段/枚举常量/λ 捕获对象都经 `cjk_gc_add_root`（M4/M5 已接，做一次全量 grep 核对，缺则补）。
- 独立脚本 `原生/测试/GC压力.ps1`：抽出校验里的 30 万次 `新建 点` 用例，再加 2–3 组（长字符串拼接收缩、集合反复增删、深层对象图），断言退出码 0 + 结果文本 + 峰值工作集无持续线性增长（用 `Get-Process.PeakWorkingSet64` 采样）。
- 文档纠偏：ADR-006、路线图 6.7/9 节、M4 spec 中"Boehm 一期推荐/后续可替换"改为"自研保守标记-清除（M4 已实现），Boehm 为未采纳备选"。

**验收**：`GC压力.ps1` 全通过；`校验.ps1 -含原生` 仍 0；35 课对拍无回退。

### 子项 3：基准回归门槛

**目标**：让基准能发现"性能回退"，而不是只比较 C 与 LLVM。

**动作**：

- `基准.ps1` 固化 M6 记录值为脚本常量 `基线 = @{ 递归斐波那契=1.015; 长循环=1.010; 字符串拼接=1.000; 键值表读写=0.971 }`（LLVM/C 比值）。
- 断言：M6 基线是历史机器实测，跨机器有相对漂移（实测键值表从 0.971 漂到 1.032）——**只在「偏移超 ±0.05 且比值 > 1.05」时判性能回退**，两个门槛取宽松者；偏移单独超 ±0.05 仅作软提示、不进硬断言。这样既保留 M6 信息，又不因机器差异误报（不把绝对毫秒写入断言）。
- 扩展为多后端基线：新增 JVM 后端作为参考列（用 `cjc.ps1 编译` + `java` 跑同一份源码），只打印比值、不设硬门槛（JVM 启动/JIT 抖动大，避免 CI 不稳定）。
- 输出格式：`C 后端 / LLVM 后端 / JVM 参考 / LLVM-C 比值 / M6基线 / 偏移`，末尾结论行由 `基准结论：LLVM 不慢于 C` 升级为 `基准结论：LLVM 不慢于 C 且比值未回退（M6 基线仅参考）`。

**风险与坑**：

- JVM 参考列只作参考，绝不进 `校验.ps1` 硬断言；机器差异用比值而非绝对时间。
- `基准.ps1` 现有中文 exe 名进程清理逻辑（`:17-31`）与 Start-Process 代理变量冲突（此前踩过）需保留规避。
- 实测校准：2026-11-20 本机四用例 C≈1037ms / LLVM≈1060–1080ms，比值 1.022–1.035；键值表偏移 +0.061 属机器漂移（LLVM 仅慢 3.2%），不应判为回退。

### 子项 4：优化级别验证与调优接口

**目标**：确认 -O2 是否最优、是否值得 LTO / `-march=native`，留下可复现报告。

**动作**：

- 在 `驱动.ps1` 增加可选开关 `-优化 <O0|O1|O2|O3|Os>`（默认 O2，行为与现在完全一致），仅替换 clang 的 `-O2` 参数；LTO/`-march` 作为**实验分支**，不进默认路径。
- 用 `基准.ps1` 对 O0/O1/O2/O3/Os 各跑一轮（同机、同重复数），写 `文档/原生/M12/基准报告.md`。
- 若某档显著更优且不影响 35 课对拍与 DWARF 断言，再讨论是否改默认值——**本里程碑默认仍保持 O2**。

**风险与坑**：

- `-march=native` 产物不可跨机移植，默认禁用。
- LTO 需要 `llvm-ar` / `lld` 配合（本机用 binutils `ar` 替代，见路线图 13 节），可能不可用；不可用则报告说明，不强行接入。
