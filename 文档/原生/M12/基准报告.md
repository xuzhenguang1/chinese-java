# M12 优化级别基准报告

> 采集日期：2026-11-20，同一台 Windows 机器、`重复 = 2` 取每档最小值。
> 命令：`.\原生\测试\基准.ps1 -重复 2 -优化 <档> -仅测量`。
> `-仅测量` 跳过 M6 基线硬门槛，只采数据；默认调用（校验链路）仍带门槛断言。

## 结论先行

**默认保持 `-O2`，不改动。** 五档 LLVM/C 比值都在 1.0 附近（约 0.998–1.049），
没有哪一档稳定显著优于其他档；差异落在测量噪声内。优化级别开关已可用
（`原生/驱动.ps1 -优化 O0|O1|O2|O3|Os`，默认 O2），LTO / `-march` 未启用——
原生运行时是保守 GC + 解释器式对象模型，热点在字符串与对象操作而非数值循环，
现有数据没有给出引入实验分支的依据。

## 数据解读与坑

- **绝对毫秒不可用于断言**：四用例复杂度差异极大（fib(28)×3、2000 万次循环、
  2 万次拼接、1 万次哈希），但 C 后端耗时一律 ~1030ms、LLVM ~1050ms——
  每个 exe 的进程启动 + 运行时初始化固定开销（约 1 秒）淹没了实际计算时间。
  这是既有基准脚本的口径，故门槛只看 **LLVM/C 比值**（同机同次运行，启动开销相消），
  不写入绝对毫秒。
- **JVM 参考列**（~210–314ms）启动远快于静态链接的原生 exe，但 JIT 抖动大、
  与 M6 基线不同源，只作展示，绝不进硬断言。
- **M6 基线漂移**：键值表基线 0.971（历史机器 LLVM 略快）在本机漂到 1.008–1.049
  （LLVM 略慢），属机器差异而非回退。因此门槛设计为「偏移超 ±0.05 **且** 比值 > 1.05
  才判回退」，取两门槛宽松者；单独超 ±0.05 只作软提示。
- **复现**：各档数据受机器负载影响会有波动，本报告数值是单次采集快照，
  结论（各档无显著差异、保持 O2）才是可复用的判断。
