## 2. 内存检查（批次一 T2）

### 2.1 E1 阶梯实测结论

**ASan 可用性**：本机 clang 23.1.5（msys2 mingw 构建，Target: x86_64-w64-windows-gnu）**不含 musl target 的 ASan 运行时**。最小链接探针：
```
ld.lld: error: cannot open .../lib/clang/23/lib/x86_64-unknown-linux-musl/libclang_rt.asan_static.a: No such file or directory
ld.lld: error: cannot open .../lib/clang/23/lib/x86_64-unknown-linux-musl/libclang_rt.asan.a: No such file or directory
```
根因：Windows 版 clang 的 resource dir 只有 windows-gnu 目标的 ASan runtime，无 linux-musl 目标。加之运行时堆分配走自建 GC（`cjk_gc_alloc` 不经 malloc），即便 ASan 可链接，GC 对象池也不会被 redzone 化。

**降级决策**：按 ADR-020 E1 阶梯 → **阶梯 B：Clang 静态分析**（`clang --analyze`）。实测静态分析器可用且能检测内存问题（对注入的 overflow 探针报 `Potential leak of memory [unix.Malloc]`）。

**实现**：驱动 `-内存检查` 旗标自动探测 ASan runtime，缺失则降级并打印：
```
内存检查：musl ASan 运行时缺失，降级为 Clang 静态分析（ADR-020 阶梯 B）。
```
静态分析告警写入 `构建/原生/静态分析报告.txt`（本次 40–41 条，均为分析器保守的 null 解引用/除零/流空指针告警，非确定缺陷），**只汇总记录、不设硬门槛**；ELF 产物照常可运行。
