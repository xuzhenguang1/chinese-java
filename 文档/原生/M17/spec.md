# M17 质量体系闭环 · 方案（spec）

> 状态：待评审。2026-11-22 产出。前置 M16 已完成并推送（`d2015e9`），浮点/集合口径已冻结。
> 来源：《后续路线计划书-M15至M18》第 5 节 + 用户 2026-11-22 四项对齐决策（见 §2）。
> 交付节奏：**分两批**——批次一「本机质量网」（可独立提交），批次二「双矩阵 CI」（前置批次一通过）。

## 1. 目标 / 非目标

**目标**：补齐路线图第 8 节承诺但一直未闭环的三项，并把 M16 建立的白名单/锚点治理接入自动化——

1. **随机 Token 模糊测试**：固定种子、三类健壮性断言（不崩溃 / 不挂起 / 中文诊断命中已知 CJK 码）、失败样本落盘可复现。
2. **Linux 内存检查**：驱动加 `-内存检查` 旗标，实测 musl 静态 ASan；按对齐决策以 ASan 优先、不可行时分降级回退，边界写进 ADR-020。
3. **双矩阵 CI**：`校验.yml` 扩为 windows-latest + ubuntu-latest，按已拍板 D3 在 ubuntu job 跑 **ELF 全量对拍**；资产现场下载 + Actions cache。
4. **白名单治理自动化**：把 M16 的锚点可追溯检查纳入 8.16 与模糊断言，做到"每条差异可追溯到 ADR"。

**非目标**：
- CI 不复现本机性能基线（性能数值仍以本机为准，CI 只做功能对拍）。
- 不做跨架构矩阵（仅两平台 x86_64）、不做云主机。
- 不把 ELF 运行资产（qemu/Alpine/musl 二进制）提交入库——延续 `.gitignore:2 构建/` 惯例，CI 现场下载 + cache。
- 不修运行时 GC 的分配机制（除非 ASan 实测证明必须加 poison 钩子，届时作为 ADR-020 的边界记录，非本里程碑强求）。

## 4. 核心设计

### 4.1 模糊测试 `原生/测试/模糊.ps1`（批次一）

- Token 池：读三表中文侧键（跳过 `#` 与 `[段名]`），按权重随机抽取拼成"看起来像程序"的 token 序列；固定种子（`System.Random(seed)`）保证可复现；默认 N 轮（建议 200，命令行可调）。
- 三类健壮性断言（**不做输出对拍**）：
  1. **不崩溃**：被检对象为 `cjc 检查`/`cjc 转译` 与原生 `编译`（可选），进程无系统级崩溃信号；对前端只要求诊断退出码在已知集合（0/1/2），非异常终止。
  2. **不挂起**：每轮固定超时（复用 `运行器.ps1 -超时秒` 思路，默认 10s），超时即记失败并落盘样本。
  3. **中文诊断**：stderr 若非空，须命中已知 CJK 码 `CJK\d{3}` 或中文关键字提示；英文异常栈/裸 NPE 视为失败。
- 失败样本落 `构建/模糊失败样本/`（构建产物，不提交），记录种子 + 轮次 + token 序列 + stderr，保证可复现。
- 白名单治理接入：模糊捕获到的诊断若命中 `差异白名单.txt` 条目，须其锚点在 ADR-007 正文存在（复用 M16 8.15 检查逻辑），否则记失败。

### 4.2 内存检查（批次一）

**驱动 `-内存检查` 旗标**（`原生/驱动.ps1`）：
- 正交于 `-无缓存/-优化/-平台/-清单`；仅在 `-平台 linux` 生效（Windows 给中文提示并忽略，或明确拒绝——实施时定，写进 spec 修订）。
- 编译点 `:231/620/642/770/799` 追加 `-fsanitize=address -fno-omit-frame-pointer`；链接点 `:262-264` 追加 ASan 链接参数。
- **强制并入 `取工具链哈希`（`:155-173`）**，确保 ASan 产物独立缓存分桶。

**E1 实测降级阶梯**（强制门槛，写进 ADR-020）：
1. 先实测 musl 全静态 + ASan 能否链接、能否 `__asan_init`、运行时能否捕获注入错误。
2. 若链接/运行失败 → 降级 **Clang 静态分析**（`-fanalyzer` 或 `scan-build`），记录 ASan 不可用的具体原因。
3. 若 ASan 可链接但因 GC 对象池不经 malloc 导致检测形同虚设 → 评估在 `gc.c:cjk_gc_alloc` 加 `__asan_poison_memory_region`/`unpoison` 钩子（**可选**，仅当实测证明必要且风险可控）；否则降级 valgrind（需先造动态 musl 构建路径）。
4. 断言随当前阶梯降级：ASan 可用则断言无 leak/overflow；降级则断言对应工具无告警，**不写成不可降级的 ASan 硬门槛**。

**`原生/测试/内存检查Linux.ps1`**：复用 GC 四组 + 第 20/21 课异常 + 第 27 课文件 IO + 网络冒烟，走 `运行器.ps1 -平台 linux` → 解析 `.elf.out/.exit`；ASan 报告收集到 `构建/` 并断言无 leak/overflow。

### 4.3 双矩阵 CI（批次二）

- `校验.yml` 扩 `strategy.matrix: { os: [windows-latest, ubuntu-latest] }`，JDK 25 temurin。
- Windows job：现有 `校验.ps1`（非原生全量）不变。
- Ubuntu job（D3）：
  1. apt 装 `qemu-system-x86`、`python3`。
  2. 从 M14 报告 URL 下载内核 `linux-virt-6.6.142-r0.apk`（解包 `boot/vmlinuz-virt`）+ minirootfs `3.20.3` + musl-dev/musl 1.2.5-r4 → 落到 `构建/工具链/`，按 M14 报告的 URL/字节数/补充 SHA256 校验。
  3. Actions cache `构建/工具链/`（key 含资产版本，版本变了自动失效）。
  4. 复用 `构建initramfs.py` + `运行VM.py` + `对拍ELF.ps1` 跑 ELF 全量对拍（35 课 C/LLVM、示例工程、自举不动点、DWARF、GC、网络冒烟）。
  5. DWARF 用 E3 可配置 readelf（系统 readelf）。
- **CI 前置改造**（两处硬编码，批次二开工第一件事）：`运行器.ps1:57-58` 与 `运行VM.py:13-15` 改为 `CJK_QEMU` / `CJK_KERNEL` / `CJK_ALPINE` 环境变量覆盖，本机未设时回退原 E: 路径（零回退）。
- **超时与熔断**：`运行VM.py` 单课超时上限（默认 180s，可配）；CI job 级 `timeout-minutes`（建议 60）；串口日志保留便于定位；必要时把网络冒烟拆独立 job。

### 4.4 白名单治理自动化（批次一）

- 8.16 块（插 `校验.ps1:1553`）静态断言：
  - 文件齐备：ADR-020、ADR-008 修订、`模糊.ps1`、`内存检查Linux.ps1`、`校验.yml` 双矩阵文本、`运行器.ps1`/`运行VM.py` 可配置路径文本。
  - ADR 计数 19 → 20（`:679/:682`）。
  - 沿用 8.15 的锚点可追溯检查（白名单每条 + 浮点已知差异每条 → ADR-007 锚点存在），8.16 追加"模糊脚本含 CJK 码断言文本"静态检查。

```
批次一（本机质量网，可独立提交）
  T0 ADR-020 立项 + ADR-008 修订 + M14 报告补 SHA256
  T1 模糊.ps1 + 三类断言 + 失败落盘
  T2 驱动 -内存检查 + E1 实测阶梯 + 内存检查Linux.ps1
  T3 校验 8.16 + ADR 计数 20 + M17 文档四件套
  → 本地 `校验.ps1 -含原生` 退出码 0 后提交

批次二（双矩阵 CI，前置批次一绿）
  T4 路径参数化（运行器.ps1 + 运行VM.py）→ 本地模拟 Linux job（含 VM）跑通
  T5 CI 资产构造脚本 + Actions cache + 校验.yml 双矩阵
  → 提交后确认两 job 均绿（含 ELF 全量对拍轮次）
```

## 6. 验收口径

1. 模糊测试固定种子 N 轮：无崩溃、无挂起（超时即失败）、诊断均中文且命中已知 CJK 码；失败样本可复现。
2. 内存检查：按 E1 当前阶梯跑通 GC 四组 + 异常 + 文件 IO + 网络冒烟；对应工具报告无 leak/overflow；降级原因与边界写进 ADR-020。
3. 双矩阵 CI 两 job 均绿；ubuntu job 完成 ELF 全量对拍（35 课 C/LLVM + 示例工程 + 自举不动点 + DWARF + GC + 网络冒烟）。
4. 35 课、快照、自举不动点零回退；`校验.ps1 -含原生` 新增 8.16 后退出码 0；ADR 计数 20。
5. CI 与本机共用 `构建initramfs.py`/`运行VM.py`/对拍脚本，资产版本与 M14 报告一致（含新补 SHA256），不出现两套口径漂移。
6. 本机零回退：E3 可配置 readelf 未设环境变量时行为与现状一致；`运行器.ps1`/`运行VM.py` 路径参数化后本机 E: junction 路径照常工作。

## 7. 风险与回退

| 风险 | 缓解 |
| --- | --- |
| musl 全静态 ASan 链接/运行失败 | E1 强制阶梯：ASan → Clang 静态分析 →（可选 poison 钩子）/ valgrind；断言随阶梯降级，不写硬门槛；边界写进 ADR-020 |
| GC 对象池不经 malloc 致 ASan 检测失效 | 实测注入已知错误验证检测有效性；无效则评估 `gc.c` poison 钩子或降级，不强求 |
| CI Linux job 因 JRE/路径差异失败 | 批次二先本地模拟完整 Linux job（含 VM 启动）跑通再改 CI；分步提交便于定位 |
| E: junction / 硬编码路径在 CI 失效 | T4 两处路径参数化，本机回退原值零回退；CI 用 `CJK_*` 环境变量 |
| CI 下载资产无完整性校验 | T0 补 M14 报告内核/rootfs SHA256，CI 下载后校验 |
| CI 跑 ELF 全量变慢/变脆（D3 已知代价） | Actions cache 资产；单课超时 + job `timeout-minutes`；串口日志保留；长耗时项可拆独立 job |
| CI 与本机 ELF 口径漂移 | 共用打包/VM/对拍脚本；资产版本/URL/SHA256 单一来源在 M14 报告 |
| 模糊"挂起"难界定 | 固定种子 + 固定超时 + 失败样本落盘，断言可复现 |
| DWARF 脚本强依赖 Windows readelf | E3 可配置化，CI 用系统 readelf、本机保持原路径 |
