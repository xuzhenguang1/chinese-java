# ADR-007 语义兼容与差异白名单

- 状态：已接受（M0）；M16（2026-11-22）实证修订，状态不变
- 日期：2026-11-09（初版）；2026-11-22（M16 浮点实证与白名单治理）
- 关联：路线图第 6.8、8 节；M16 语义兼容实证

## 结论

原生后端以 **JVM 后端为参考实现**，目标是同一中文源在两边的 stdout 逐字节一致、退出码一致。无法一致的项必须登记在 `原生\测试\差异白名单.txt`，每条对应本 ADR 的条目，禁止口头豁免。

必须显式处理、不得依赖 C 默认行为的语义点：

| 语义点 | JVM 行为 | C 默认行为 | 原生后端处理 |
| --- | --- | --- | --- |
| 整数溢出 | 按 32/64 位回绕 | 有符号溢出未定义 | `-fwrapv` + 无符号运算 |
| 整数除法 | 向零截断，除零抛异常 | 除零未定义 | 插入除零检查，抛 `算术异常` |
| `整数.最小 / -1` | 回绕为 `整数.最小` | 未定义 | 特判 |
| 移位 | 移位数按位宽取模 | 超宽未定义 | 先掩码 |
| 数组越界 | 抛 `数组越界异常` | 未定义 | 每次读写插检查 |
| 空引用 | 抛 `空指针异常` | 段错误 | 每次解引用插检查 |
| 字符串拼接 `空` | 输出 `null` | 未定义 | 运行时统一处理 |
| 浮点打印 | 最短可回读表示（`Double.toString`） | `%g` 结果不同 | 自研可回读最短表示 + Java 风格规范化（`cjkrt.c:399-493`）；M16 边界实证，M20 根治次正规数差异（回读循环 p 从 1 起，符合 Java「小数至少一位」），7/7 逐字节一致、无已知差异 |
| 无序集合遍历 | `HashMap` 顺序不保证 | 自研表顺序不同 | 原生为插入序平行数组（`集合.c:31-36,339-345,470-516`），对拍只用 `链式键值表`，已确认一致、非豁免 |
| 默认 `哈希码` | 身份哈希 | 地址哈希 | 原生实现 Java `hashCode()` 语义（`值.c:320-345`，C/LLVM 内建调用）；不比较具体数值 |

### 差异处置与收敛状态（M16 更新）

早期设想的三类豁免（无序集合顺序、默认 `哈希码` 数值、浮点末位）**均已收敛，不在白名单中**：

1. 无序集合遍历顺序：原生确认为插入序（`集合.c`），对拍统一用 `链式键值表`，逐字节一致，无需豁免。
2. 默认 `哈希码` 数值：原生实现 Java `hashCode()` 语义；对拍不比较具体数值，属判据约定而非豁免。
3. 浮点最短表示：自研可回读最短表示已收敛到 35 课逐字节一致；M16 新增边界实证发现次正规数 1 处差异（登记于「已知限制」），**M20 已根治**——回读循环 p 从 1 起（对齐 Java「小数至少一位」规则），次正规数 `4.9E-324`/`9.9E-324` 与 Java 逐字节一致，浮点边界 7/7 无已登记差异，该已知限制已撤销。全程**不进白名单**。

**当前白名单**（`原生\测试\差异白名单.txt`）仅一条，且必须有本 ADR 条款可追溯：

- `^随机整数：-?\d+$` —— 依据「已知限制」第 1 条（随机源不可确定）。

治理规则：白名单每条须在本 ADR 有对应条款（以锚点 `ADR-007:<标识>` 标注）；新增条目必须先改本 ADR、再改白名单文件；校验脚本静态检查此可追溯性。

## 理由

1. 「逐字节一致」是最便宜、最可信的对拍判据；一旦允许模糊比较，语义漂移会长期潜伏。
2. 浮点打印与无序集合是仅有的两处结构性难点，必须在架构阶段定性，不能等测试失败再补丁。
3. 白名单与 ADR 绑定，能阻止「为了让测试变绿而随手加豁免」。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只比较语义等价、不比较文本 | 无法发现格式与顺序回归 |
| 全部使用 C 默认行为 | 溢出、除零、越界都会变成未定义行为 |
| 运行时全用 64 位整数 | 与 Java `int` 溢出行为不一致 |

## 已知限制

> 本节登记"无法逐字节一致且不进白名单"的差异，每条带锚点，供白名单可追溯性与 M16 边界实证引用。

1. **锚点 `ADR-007:随机源`** —— 随机整数由 JVM（`ThreadLocalRandom`）与原生各自随机源生成，数值不可确定、不可逐字节一致。处置：白名单正则 `^随机整数：-?\d+$` 过滤。范围仅限数值本身，其余输出仍逐字节比较。
2. ~~**锚点 `ADR-007:浮点边界`** —— 次正规数最短表示差异（M16 实证确认）~~ **已于 M20 根治并撤销（2026-11-24）**：
   - M16 记录：原生从 `p=0` 起找可回读最短位，`%.0e` 得 `5e-324` 回读即停，输出 `5.0E-324`；Java `Double.toString` 取 `4.9E-324`（规范要求小数部分至少一位）。
   - M20 修复：`cjkrt.c` 回读循环起点 `p=0` → `p=1`，符合 Java「小数至少一位」规则。实测 82510 随机 double，`p0→p1` 仅改变 7 个次正规数（全为修正、零回归）；`1.0`/`0.1`/正常值/`%f`/特殊值口径不变。
   - 验证：浮点边界 C/LLVM 双后端各 7/7 逐字节一致，`minvalue=4.9E-324`、`9.9E-324` 与 JVM 输出原始字节相等（未走归一化）；`浮点已知差异.txt` 的 `^minvalue=.*` 行与锚点同步撤销。

## 验收口径

- 对拍脚本比较 stdout 字节与退出码；stderr 只比较关键行（异常名与行号）。
- 白名单条目与本 ADR「已知限制」条款一一对应（锚点 `ADR-007:<标识>`），校验脚本静态检查可追溯性。
- 浮点与无序集合已按插入序/可回读最短表示收敛；M16 边界实证结论与剩余差异记入「已知限制」，不再设 M5 之类的时限。

## 影响

- 测试数据默认使用 `链式键值表` 与有序输出，避免无意义的顺序差异。
- 任何新增白名单条目都必须先改本 ADR，再改白名单文件。
