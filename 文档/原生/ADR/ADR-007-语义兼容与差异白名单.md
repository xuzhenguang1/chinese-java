# ADR-007 语义兼容与差异白名单

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 6.8、8 节

## 结论

原生后端以 **JVM 后端为参考实现**，目标是同一中文源在两边的 stdout 逐字节一致、退出码一致。无法一致的项必须登记在 `原生\测试\差异白名单.txt`，每条对应本 ADR 的条目，禁止口头豁免。

必须显式处理、不得依赖 C 默认行为的语义点：

| 语义点 | JVM 行为 | C 默认行为 | 原生后端处理 |
| --- | --- | --- | --- |
| 整数溢出 | 按 32/64 位回绕 | 有符号溢出未定义 | `-fwrapv` + 无符号运算 |
| 整数除法 | 向零截断，除零抛异常 | 除零未定义 | 插入除零检查，抛 `算术异常` |
| `整数.最小 / -1` | 回绕为 `整数.最小` | 未定义 | 特判 |
| 移位 | 移位数按位宽取模 | 超宽未定义 | 先掩码 |
| 数组越界 | 抛 `数组越界异常` | 未定义 | 每次读写插检查 |
| 空引用 | 抛 `空指针异常` | 段错误 | 每次解引用插检查 |
| 字符串拼接 `空` | 输出 `null` | 未定义 | 运行时统一处理 |
| 浮点打印 | 最短可回读表示 | `%g` 结果不同 | 移植 Ryu / Java 浮点转文本算法 |
| 无序集合遍历 | `HashMap` 顺序不保证 | 自研表顺序不同 | 对拍只用 `链式键值表` |
| 默认 `哈希码` | 身份哈希 | 地址哈希 | 不比较具体数值 |

白名单初始条目：

1. `HashMap` / `HashSet` 等无序集合的遍历顺序：允许不同，但元素集合必须相同。
2. `默认 哈希码` 的具体数值：允许不同，只保证同一对象在单次运行内稳定。
3. 浮点最短表示在移植 Ryu 完成前：允许末位差异，M5 前必须移入「逐字节一致」。

## 理由

1. 「逐字节一致」是最便宜、最可信的对拍判据；一旦允许模糊比较，语义漂移会长期潜伏。
2. 浮点打印与无序集合是仅有的两处结构性难点，必须在架构阶段定性，不能等测试失败再补丁。
3. 白名单与 ADR 绑定，能阻止「为了让测试变绿而随手加豁免」。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只比较语义等价、不比较文本 | 无法发现格式与顺序回归 |
| 全部使用 C 默认行为 | 溢出、除零、越界都会变成未定义行为 |
| 运行时全用 64 位整数 | 与 Java `int` 溢出行为不一致 |

## 验收口径

- 对拍脚本比较 stdout 字节与退出码；stderr 只比较关键行（异常名与行号）。
- 白名单条目数与其对应 ADR 条目一一对应，校验脚本检查文件存在且格式合法。
- 浮点与无序集合的差异在 M5 前逐项收敛，收敛后从白名单删除。

## 影响

- 测试数据默认使用 `链式键值表` 与有序输出，避免无意义的顺序差异。
- 任何新增白名单条目都必须先改本 ADR，再改白名单文件。
