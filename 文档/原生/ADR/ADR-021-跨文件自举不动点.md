# ADR-021：M18 跨文件自举不动点

- 状态：Accepted（2026-11-22 用户拍板 F1–F4，实施见 `文档/原生/M18/`）
- 日期：2026-11-22
- 关联：后续路线计划书第 6 节、ADR-011～015（自举一期～五期）、ADR-019（M15 包管理）、ADR-020（M17 质量体系）、用户 2026-11-22 决策 F1/F2/F3/F4 + 历史 D4
- 前置：M15–M17 已完成并推送（`c7d5da1`），模糊/内存/双矩阵 CI 保护网就位，浮点与集合口径冻结

## 背景

自举一期～五期实现了「词表 → 分词 → 语法 → 语义 → 中间码 → 自举」五层单文件能力，但语义与中间码层**逐文件独立分析、不共享符号表**：每文件各自新建 `语义检查器`，跨文件类/接口引用无法在方法体分析中解析。参考实现 `语义分析器.分析模块`（`原生/中间表示/src/中文/原生/中间/语义分析器.java:222-245`）早已支持跨文件两阶段分析，但自举侧没有对应命令，也没有跨文件不动点证据。

M15 已提供中文 DSL 依赖清单解析（`工具/cjc/依赖清单.java`，输出首行入口 + 其余有序源），M17 已提供模糊/内存/CI 保护网，第一次具备安全改造 8554 行中文单文件的条件。

2026-11-22 逐行实测发现三处必须处理的约束：
1. `自举前端.java:8176-8273 语义命令.run` 与 `:8498-8554 中间命令.run` 的单文件循环是 35 课快照与 175 组不动点的输出来源，**任何字节变化都算回退**。
2. 改 `自举前端.java` 必然改变它对自身源码的 MIR 输出，`原生/测试/MIR快照/自举前端.mir.txt`（改造前 SHA256 `52db76b85a5b695f346aab1c8cce1cb5b601368fc36037b7584c179508a380c1`，45108 内容行）一次性失效。
3. 参考侧 `前端主程序.java:46-105` 只有 `编译模块`/`编译模块LLVM`，**没有** `语义模块`/`中间模块`，跨文件文本对拍缺少参考入口。

## 决策

### 1. 中文版两阶段分析器（复用，不另造）

在 `自举前端.java` 的 `语义检查器`（`:3850`）内新增模块方法，全部复用现有字段与方法，**不复制第二份语义实现、不改参考 `语义分析器.java`**：

1. **pass1 注册**：`注册内建类()` 只调用一次；逐单元 `收集类(声明, 空)`，不做脚本兜底（对齐参考 `:215-216`），避免重复入 `全部类`。
2. **pass1 尾校验**：导入未找到（模块内类放行、`java`/`javax` 忽略）→ 引用类型不可解析 → 入口不唯一，顺序固定，中文消息与参考逐字节一致。
3. **pass2 分析**：在全部类已注册后调一次 `分析全部()`（`:4376`），使跨文件方法体可解析。
4. **产出**：调 `生成程序()`（`:5795`）产出单个 `中间节点` 程序。

单文件路径：`语义` / `中间` 命令检测恰好 1 个源时**原样执行现有循环**，输出与基线逐字节一致；模块逻辑只在新命令进入。

### 2. 跨文件命令与双输入契约（F1-C）

```
自举前端 语义模块 <根> <入口源> <其他源...>
自举前端 中间模块 <根> <入口源> <其他源...>
自举前端 语义模块 <根> -清单 <依赖清单.txt>
自举前端 中间模块 <根> -清单 <依赖清单.txt>
```

- **形式一（显式列表）**为主对拍口径，参数顺序与参考 `编译模块 <根> <输出> <入口> <其他源...>` 一致（入口在第一个）；脚本侧用 `cjc 依赖 解析` 展开。
- **形式二（exe 自读清单）**：在自举单文件内实现 `依赖清单.java` 的五行 DSL（`包名`/`版本`/`入口`/`源目录`/`依赖`），**不引正则**；复用已有 `拆行`，但 `切分词` 按逗号切分、不适用 DSL 的空白分隔，另加同文件内的 `切空白词`（逐字符扫描空格/Tab/换行）；一期边界与 M15 相同——本地路径 + 精确版本，不做远程与范围求解。源文件按**文件名**去重，避免 `源目录 .` 展开产生 `基\.` 与 `基\` 两种路径文本导致入口重复收集。
- **一致性硬断言**：同一份样例，两种输入必须产出同一组有序源文件（入口相同、其余按路径排序），语义/MIR 输出逐字节一致；由 `对拍自举模块.ps1` 专项项锁定。
- 自举 `中间模块` 输出单个 MIR 程序，不打印 `// 文件名` 分段前缀；原 `中间` 命令多文件分段口径不变。

### 3. 参考侧对拍入口（F2-A）

在 `前端主程序.java:46-105` switch 加 `语义模块` / `中间模块`，复用 `:768-789 分析模块程序` 解析单元并调 `分析模块`，按自举侧同格式打印语义表与 MIR 文本。**不改** `语义分析器.java`。

### 4. 基线迁移（F3-A）

- 改造前：`自举前端.mir.txt` 复制为 `自举前端.历史.mir.txt` 只读对照，SHA256 记入 `M18/对拍报告.md`。
- 改造后：重新生成 `自举前端.mir.txt` 作新不动点锚点，由 A/B 双 exe 交叉确认，新 SHA256 记入对拍报告。
- 35 课 35 份 MIR/AST/语义快照不受影响，保持逐字节不变。

### 5. 专用样例边界（D4 不变）

另建 `原生/测试/自举多文件样例/`，6–8 文件，覆盖 pass1 跨文件注册、跨文件继承+重写、跨文件接口实现、包声明与 `java.*` 导入、唯一入口；负例三例（双入口 / 未找到导入 / 引用不存在类型）独立目录。**示例工程 3 包 10 文件不作风控不动点样本**，仅验证零回退。

### 6. 等价不动点口径

沿用 M11 口径：A 用改造后新前端重编，与 B 同源同参独立编译；比较文本输出（自身 MIR、跨文件语义/MIR、175 组五命令），**不比 exe 二进制哈希**（链接时间戳不稳定）。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| exe 仅收显式列表（F1-A） | 部分采纳 | 作为主对拍口径；用户 F1-C 要求双输入，另加 exe 自读清单 |
| exe 自读清单替代显式列表（F1-B） | 未采纳 | 丢失与参考 `编译模块` 对齐的签名 |
| 参考侧用 `编译模块` 间接对拍（F2-B） | 未采纳 | 丢失语义表与 MIR 文本层逐字节证据 |
| 只比 A/B 两实现（F2-C） | 未采纳 | 无法发现与参考实现的语义漂移 |
| 隔离到新文件 `自举模块.java`（F3-B） | 未采纳 | 不动点「自举自身」从一份变两份，驱动需多源编译，违背单文件口径 |
| 不迁移基线（F3-C） | 未采纳 | 改造后必然红 |
| 分两批 / 三批交付（F4-A/C） | 未采纳（F4-B） | 用户选择一次到位；内部仍按 T0→T5 硬门槛推进，不设中间提交点 |
