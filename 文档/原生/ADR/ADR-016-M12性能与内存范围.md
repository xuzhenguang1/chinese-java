# ADR-016：M12 性能与内存范围（影子栈、GC 加固、基准门槛、优化调优）

- 状态：已采纳并落地（T1–T7 全部完成，2026-11-20 全量校验通过）
- 日期：2026-11-19
- 关联：M11 实施计划第 7 节、路线图第 7 节 M12、ADR-006（运行时与对象模型）、ADR-007（语义兼容与差异白名单）、ADR-008（测试与对拍）、ADR-009（LLVM 后端与调试信息）

## 背景

M11 之后规划了 M12「性能与内存」，方向写着：自研标记-清除 GC、影子栈、基准门槛、-O2 调优。
开工前核查实现现状，发现计划文字与代码事实存在两处偏差，必须先定性，避免重复造轮子：

1. **自研标记-清除 GC 在 M4 已实现**（`原生/运行时/gc.c`：保守标记-清除、块内指针定位、阈值自适应、TEB.StackBase 根扫描），
   并非待实现项。ADR-006 与路线图 6.7/9、M4 spec 仍写「一期 Boehm / 后续可替换」的旧口径。
2. **-O2 已在 `原生/驱动.ps1` 全部编译路径启用**（`:171/518/540/632/645`），也不是待实现项。
   「-O2 调优」的真实含义是验证是否最优、是否值得 LTO/-march，并留下可复现报告。

真正未落地的是「影子栈」与「基准回归门槛」。

## 决策

### 1. M12 = 影子栈（新增）+ GC 加固 + 基准门槛 + 优化验证

- **影子栈**：新增显式调用帧链（`cjk_frame`），C 与 LLVM 后端在方法入口/出口与异常路径埋点，
  未捕获异常逐帧打印中文调用栈。异常跳转仍用 setjmp/longjmp，不做 DWARF 栈展开。
  帧内容用生成期静态字符串（UTF-8），不分配堆内存；深度上限 1024 帧。
- **GC 加固**：保留 M4 保守标记-清除算法核心；显式化「多线程存活时暂停自动回收」策略并提供状态查询；
  核对静态字段/枚举/λ 捕获的根登记覆盖；压力用例从校验脚本抽成独立 `GC压力.ps1`。
- **基准门槛**：固化 M6 记录值 1.015/1.010/1.000/0.971 为脚本常量；实测发现基线跨机器会相对漂移
  （键值表 0.971 → 本机 1.032），故门槛定为「偏移超 ±0.05 且比值 > 1.05 才判回退」（取宽松者），
  单独超 ±0.05 仅作软提示；新增 JVM 参考列（只打印、不进硬断言，规避 JIT 抖动）。
- **优化验证**：驱动暴露 `-优化 O0|O1|O2|O3|Os`，默认保持 O2；LTO/-march 仅实验分支，不进默认路径；
  各档实测写入 `文档/原生/M12/基准报告.md`。

### 2. 口径纠偏：GC 为自研实现，Boehm 是未采纳备选

- 把 ADR-006、路线图 6.7/9 节、M4 spec 中「一期接 Boehm / 后续可替换」改为
  「自研保守标记-清除（M4 已交付）；Boehm 因未安装且需引入第三方依赖，未采纳」。
- 这不改变运行时行为，只让文档与实现一致，避免后续里程碑误判 GC 为待办。

### 3. 不变量：对拍与异常首行格式

- 35 课 C/LLVM 对拍、自举不动点、`校验.ps1:869-899` 未捕获异常断言（含中文异常名与源文件名、不含 `java.lang.`）
  必须继续通过；影子栈新增的是逐帧行，不改首行格式。
- 基准的绝对毫秒不写入断言（机器相关），只比较比值与对基线偏移。

## 后果

- 正面：补上唯一缺失的运行时可观测能力（逐帧中文栈）；GC/优化两项从"假待办"变成"验证 + 显式化"，省去重写风险；
  基准从相对比较升级为回归门槛，能发现性能退化。
- 代价：C 与 LLVM 两个后端都要改代码生成与 ABI 静态断言；影子栈对深递归有上限截断；
  JVM 参考列增加基准脚本运行时间，但不影响 CI 稳定性（不进硬断言）。
- 风险：longjmp 跳过正常帧 pop 会导致栈错乱，必须依赖 handler 保存/恢复帧深；影子栈帧为静态字符串，
  不涉及 GC；LTO 因本机用 binutils `ar` 替代 llvm-ar 可能不可用，报告说明即可。
