# ADR-015：M11 自举五期范围（泛型、λ 与自举自举）

- 状态：已采纳
- 日期：2026-11-18
- 关联：路线图第 7 节 M11、ADR-004（中间表示与 MIR 文本格式）、ADR-008（测试与对拍）、ADR-014（自举四期范围）

## 背景

四期（ADR-014）把教程 01–21 的 AST → MIR 降级搬到自举前端，验证了「中文 Java 能写编译器的中间码层」。
剩余 22–35 课引入内置容器、泛型类型参数、成员内部类、标准库调用表、λ/流、方法引用、
记录、密封类与 `产出`，自举前端遇到这些形态会给出「暂不支持」诊断，无法覆盖全量语料。

参考实现已经能降级上述全部形态，也能降级 `原生\自举\自举前端.java` 自身。
五期的工作是把参考口径镜像到自举侧，并把「自举自举」从一次性探针升级为可重复断言。

## 决策

### 1. 五期范围 = 22–35 课降级 + 自举自举两级验证

- 在自举前端内补齐内置类型/标准库类解析、泛型类型参数擦除口径、内部类 `__外部` 链、
  标准库与集合内建调用表、λ/方法引用合成类、记录合成成员、`产出`/切换表达式剩余形态。
- 教程 22–35 与参考实现逐字节对拍；MIR 黄金快照从 21 份扩到 35 份。
- 参考实现为 `原生\自举\自举前端.java` 生成基线；自举 exe 对同一文件产出 MIR，与基线逐字节一致（第一阶）。
- 第二阶采用**等价不动点**口径：参考实现的 C 后端只接受内存中的 `中间代码.程序` 对象，
  全仓没有「MIR 文本 -> 程序对象」的解析入口，无法按字面把第一阶 MIR 文本直接喂给 C 后端。
  因此 A 取现有自举 exe，B 用标准编译命令从同一份自举源码独立重新编译；断言 B 对自身产出的
  MIR == 基线 == A，且 B 跑教程 01–35 的词表/分词/语法/语义/中间码输出与 A 逐字节一致。
- 不比较 exe 二进制哈希：链接时间戳不稳定，只比较 MIR 文本与运行输出。

### 附：原生运行时文本构建器性能修复
- 定位：自举 exe 降级自身曾耗时 20+ 分钟而参考实现 1.2 秒；卡点在 `中间打印` 的节点遍历。
- 根因：`原生\运行时\集合.c` 的 `cjk_builder_append` 每次 `cjk_str_concat` 复制整个缓冲区，为 O(n²)。
- 修复：把文本构建器改为动态容量 UTF-16 缓冲（结构保持 24 字节以兼容类描述符），追加摊还 O(1)，
  `转文本` 时一次性快照。自举自身降级由 20+ 分钟降为约 1.2 秒。这一改动不改变输出字节，
  属于在不触碰 C 后端语义的前提下消除阻塞自举自举验收的性能缺陷。

### 2. 参考口径唯一，禁止特例绕过

- 新形态一律以 `.\cjc.ps1 原生 中间 <文件>` 的输出为唯一口径；失败时按中文诊断逐条修降级层，
  不改参考实现，不为单条用例写特例。
- 未登记的方法继续走 `失败` 诊断，禁止静默降级为错误型或空节点。
- 自举源码自身触发的新形态同样按上述规则处理；本轮共补齐字段接收者识别与静态工具名遮蔽等缺口。

### 3. 关键降级口径

| 项 | 口径 |
| --- | --- |
| 泛型类型参数 | 参考实现以 `__值` 表示；自举侧类型参数返回 `语义类型.引用型("__值")` |
| 内置容器 | `清单` / `键值表` / `集` / `文本构建器` / `流` / `可选值` 等统一降级为 `调用 内建 <名>` |
| 成员内部类 | 继承链上的字段接收者是当前实例 `这`；外层字段接收者从内层 `这` 起逐层套 `__外部` |
| λ | 含函数实参的调用合成 `__λN` 类，捕获外层局部变量为字段，方法名 `调用` |
| 方法引用 | `类::方法` 合成 `__方法引用N` 类，用于 `比较器.按整数` 等 |
| 记录 | 合成构造器、访问器、`转文本`、`等于`、`哈希码`，MIR 体直接挂在 `中间体` 上 |
| 产出 | 切换表达式块分支折叠为 `顺序表达式`，前奏语句直挂，`结果` 下挂产出值 |

### 4. λ 捕获口径

- 只捕获当前可见局部变量（含参数），不捕获字段；`这` 不是隐式捕获项。
- 字段顺序按参考 MIR：外层作用域由内到外、同层按声明/参数顺序。
- `__λN` 按单文件出现顺序从 1 递增；对拍只看单文件，不做跨文件编号稳定性假设。

### 5. 五期不做

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 多文件共享符号表 | 不做 | 与参考一致：逐文件独立分析 |
| 解释器与 C/LLVM 后端改动 | 不做 | M11 只验证到 MIR 文本与自举闭环 |
| 包管理、跨平台、性能优化 | 不做 | 超出本期语料与验收面 |
| 替换生产路径的 Java 参考实现 | 不做 | 参考实现继续作为对拍基准 |

## 备选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 让参考实现按自举侧缺口反向改写 | 未采纳 | 破坏既有 35 课黄金快照，无法归因 |
| 为自举源码中的难点写专用分支 | 未采纳 | 会产生只对自身有效的假自举 |
| 以 exe 二进制哈希判断不动点 | 未采纳 | 链接时间戳不稳定，无法作为稳定断言 |
| 只跑 22–35 子集 | 未采纳 | 一级至四期语料必须同时不回归 |

## 影响

- `原生\自举\自举前端.java` 扩展降级能力并新增自举自举断言所需缺口修复；
- `原生\测试\MIR快照\` 由 21 份扩到 35 份，另存 `自举前端.mir.txt` 作为第一阶基线；
- `原生\测试\对拍中间码.ps1` 覆盖教程 01–35、35 份快照与自举自举第一阶；
- `原生\驱动.ps1` 修复 Windows clang 中文路径链接；`校验.ps1` 新增 8.10 断言；ADR 计数 14 → 15。

## 验收

1. `.\原生\测试\对拍中间码.ps1` 输出教程 35 份、快照 35/35、自举前端自身中间码一致，通过 3/共 3 项；
2. `.\原生\测试\对拍自举不动点.ps1` 输出 `自举不动点：通过`（自身 MIR 三方一致 + 教程 35 课 × 5 命令 = 175 组 A/B 逐字节一致）；
3. `.\cjc.ps1 原生 自举` 一期 4/4、二期 3/3、三期 3/3、四期 3/3、五期 2/2（不动点）；
4. `.\工具\发布\校验.ps1 -含原生` 退出码 0，末尾 `全部校验通过。`。
