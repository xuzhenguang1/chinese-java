# ADR-008 测试与对拍策略

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 8、9 节

## 结论

原生实现的正确性以 **对拍** 为核心，辅以黄金快照、诊断一致性与内存检查：

1. **对拍**：同一中文源分别跑 JVM 后端与原生后端，比较 stdout 字节与退出码；stderr 只比较关键行。
2. **黄金快照**：AST 与 MIR 文本快照纳入仓库，文本必须确定性生成；改动快照需显式说明。
3. **诊断一致性**：`校验.ps1` 中的 13 条诊断反例与「缺标准库 jar」反例，在两套前端都要命中。
4. **模糊测试**：随机 Token 序列保证前端不崩溃、不挂起，并给出中文错误。
5. **内存检查**：Linux 用 ASan / valgrind；Windows 用 GC 压力用例与运行时断言。
6. **性能基准**：递归 fib、长循环、字符串拼接、键值表读写，分别记录 JVM 与原生数据，不设硬性门槛。
7. **跨平台 CI**：Windows（clang / MSVC 至少其一）与 Linux（clang）。

目录约定：

```
原生\测试\
  对拍.ps1            单文件或目录的 JVM / 原生输出比对
  差异白名单.txt       允许不同的项（见 ADR-007）
  快照\               AST 与 MIR 黄金快照
```

## 理由

1. 两套实现互为参考，比手写期望输出更能发现回归。
2. 黄金快照能在语义未跑通前先锁定「解析与降级是否稳定」。
3. 诊断一致性直接复用现有资产，避免新前端重新发明错误文案。
4. 模糊测试成本低，能提前暴露词法与语法边界的崩溃。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只写单元测试、不做对拍 | 无法验证两套实现的最终行为一致 |
| 只比较退出码 | 无法发现输出内容回归 |
| 手写期望输出 | 35 课与标准库规模下维护成本过高 |

## 验收口径

- M0：`.\工具\发布\校验.ps1 -含原生` 退出码 0，且新增的 M0 检查项全部通过。
- M2 起：01–10 课对拍 0 差异（白名单除外）。
- M3 起：Windows 与 Linux 各跑一遍 01–08 课。
- 每次里程碑结束，快照可重复生成，差异为零。

## 影响

- 对拍脚本必须能同时调用 JVM 链路与原生链路，且不污染用户工作目录（中间产物放 `构建\`）。
- 快照文件与白名单文件属于测试资产，随代码提交；临时产物不入库。
