# ADR-003 前端与词表桥接

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 5、12 节

## 结论

原生前端与现有 `cjc` **共用同一份词表，不复制、不派生第二份**：

- `工具\cjc\关键字表.txt`
- `工具\cjc\近义词典.txt`
- `工具\cjc\方法糖.txt`
- `工具\cjc\诊断中文表.txt`

前端启动时按只读方式加载这 4 个文件，路径固定为仓库根目录下的 `工具\cjc`；`原生\` 内出现同名文件即视为错误。

词法阶段沿用现有约定：

- 中文关键字与后继名称之间必须有空格或标点（CJK001）。
- 无法映射的全角标点阻断（CJK002）；`。` / `、` 自动纠正并提示 CJK106。
- 语法采用手写递归下降，不使用语法生成器。

`cjc.ps1` 的首个参数为 `原生` 时转发到 `原生\驱动.ps1`。这与关键字表中 `native=[原生]` 并不冲突：子命令拦截发生在调用 Java 之前，只影响命令行，不影响源码中的 `原生` 修饰符。

## 理由

1. 两套实现读同一份词表，才能保证「同一段中文源码在两边识别出的关键字集合一致」。
2. 复制词表会在下一次改词时立刻漂移，且难以被单元测试发现；单一数据源配校验脚本更可靠。
3. 手写递归下降能精确控制错误位置与中文诊断，便于与现有 13 条诊断反例对齐。
4. `原生` 子命令只在 PowerShell 包装层拦截，不污染语言关键字表。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| 复制词表到 `原生\` | 必然漂移，违反单一数据源 |
| 前端内置 Java 常量表 | 与 `工具\cjc` 形成第二份数据，改词需改代码 |
| 复用 `Cjc.java` 的转译结果 | 丢失语法结构与类型信息，无法生成机器码 |
| 语法生成器 | 诊断文案与中文词表绑定困难，生成代码难审阅 |

## 验收口径

- `.\原生\工具\词表桥接.ps1` 输出计数与关键字表表头一致：英文 56 / 中文 121 / 类型别名 34；词典 50 组；方法糖 52/3/56/10；诊断表 65 条。
- `.\cjc.ps1 原生 检查 教程` 退出码 0，且输出包含上述计数与「35 个 .java 文件 / 996 行」。
- `.\工具\发布\校验.ps1 -含原生` 断言 `原生\` 下不存在 4 个词表文件。
- M1 起，13 条诊断反例在原生前端同样命中 CJK001 / CJK002 与 5 条新手提示。

## 影响

- 任何新增关键字、近义词、方法糖或诊断规则，只需改 `工具\cjc` 下的对应文件；前端不得硬编码。
- 词表桥接脚本只做读取与计数，不参与代码生成；M1 的 Java 词法分析器需实现与 `词表.psm1` 相同的展开规则。
