# ADR-006 运行时与对象模型

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 6.4、6.5、6.6、6.7 节

## 结论

C 运行时（`原生\运行时\`）采用以下模型：

### 基本类型

| 中文类型 | C 类型 | 说明 |
| --- | --- | --- |
| `整数` | `int32_t` | 32 位补码回绕 |
| `长整数` | `int64_t` | 64 位补码回绕 |
| `双浮点` | `double` | IEEE-754 |
| `浮点` | `float` | IEEE-754 |
| `布尔` | `uint8_t` | 只取 0 / 1 |
| `字符` | `uint16_t` | UTF-16 码元 |

基本类型不装箱；泛型实参按 Java 语义装箱为堆对象。

### 对象与数组

- 对象头：`{ void** vtable; uint32_t class_id; gc_header }`，字段紧随其后，按 8 字节对齐。
- 接口调用使用 itable，类继承使用 vtable；`是` / 向下转型读 `class_id` 与父类链。
- 数组：`{ int32_t length; uint8_t element_kind; data[] }`；每次读写插入长度检查，越界抛 `数组越界异常`。
- 空引用统一用 0 指针；每次解引用插入空检查，抛 `空指针异常`。

### 字符串

- 内部为 **UTF-16 码元数组 + 长度**，与 Java `String` 的 `length` / `取字符` / `取子串` 完全一致。
- 控制台与文件边界做 UTF-8 转换；Windows 启动时设置 UTF-8 代码页。
- 字符串拼接、插值、`空` 的打印在运行时统一处理，保证与 JVM 输出一致。

### 异常

- 一期（M0–M19）用 `setjmp` / `longjmp` + 每线程异常处理器栈实现 `尝试` / `捕获` / `兜底`。
- **M20 G5 起二期口径生效（双后端单轨）**：异常控制流统一走 Itanium C++ ABI——C 后端生成 C++ `try/catch` landing、LLVM 后端生成 `landingpad`，抛出点统一为 `异常.cpp: cjk_throw`。PE 用平台 personality（`__gxx_personality_seh0`），ELF/musl 用 DWARF personality（`__gxx_personality_v0`）；不再保留 setjmp 双轨回退。
- `cjk_frame` 影子栈两后端继续保留：DWARF/SEH 只负责控制流，中文帧名、源文件与行号仍由运行时打印。
- `声明抛出` 只做编译期标注，原生后端不强制检查。

### 内存回收

- 采用**自研保守标记-清除 GC**（M4 已交付），接口封装在 `运行时\gc.c`：块内指针定位、阈值自适应、
  C 栈/静态根/setjmp 寄存器三类根；非 Win64 不扫 C 栈。
- 多线程存活期间暂停自动回收（保守扫描只看当前线程栈，会误回收其他线程活跃对象），线程退出后恢复；
  状态可经 `cjk_gc_auto_paused()` / `cjk_gc_status_text()` 查询。
- M3 前曾用临时 arena 分配，M4 已切换到 GC。Boehm 因本机未安装且需第三方依赖，**未采纳**。

## 理由

1. 与 JVM 的字符串索引、整数回绕、数组越界语义一致，才能做逐字节对拍。
2. UTF-16 内部表示避免每次 `取子串` 都做编码转换，边界只在 IO 处处理。
3. 一期 `setjmp` / `longjmp` 成本低、足以支撑 35 课对拍；二期（M20）按 G5 双后端统一到编译器展开，消除双轨语义分歧（见 ADR-023）。
4. 自研保守标记-清除实现成本低、无第三方依赖，且已能支撑 35 课对拍与 GC 压力用例。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| UTF-8 内部字符串 | `length` / `取字符` 与 Java 不一致，对拍成本高 |
| 引用计数 | 循环引用泄漏，且与 Java 语义不符 |
| 不回收（纯 arena） | 长循环内存增长，不能作为最终方案 |
| 自研标记-清除优先 | 一期风险高，留到 GC 语义稳定后 |

## 验收口径

- M4：09–21 课对拍一致，异常栈能定位到中文源行号。
- GC 压力用例（长循环创建对象与字符串）不崩溃、不出现明显泄漏。
- 空引用与越界用例抛出中文异常名，而不是段错误或英文系统错误。

## 影响

- 标准库的 C 实现必须复用同一套对象头、字符串与集合结构，不得各自定义私有布局。
- 任何改变对象头或字符串布局的改动都必须同步更新 C 后端、运行时与 GC。
