# ADR-006 运行时与对象模型

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 6.4、6.5、6.6、6.7 节

## 结论

C 运行时（`原生\运行时\`）采用以下模型：

### 基本类型

| 中文类型 | C 类型 | 说明 |
| --- | --- | --- |
| `整数` | `int32_t` | 32 位补码回绕 |
| `长整数` | `int64_t` | 64 位补码回绕 |
| `双浮点` | `double` | IEEE-754 |
| `浮点` | `float` | IEEE-754 |
| `布尔` | `uint8_t` | 只取 0 / 1 |
| `字符` | `uint16_t` | UTF-16 码元 |

基本类型不装箱；泛型实参按 Java 语义装箱为堆对象。

### 对象与数组

- 对象头：`{ void** vtable; uint32_t class_id; gc_header }`，字段紧随其后，按 8 字节对齐。
- 接口调用使用 itable，类继承使用 vtable；`是` / 向下转型读 `class_id` 与父类链。
- 数组：`{ int32_t length; uint8_t element_kind; data[] }`；每次读写插入长度检查，越界抛 `数组越界异常`。
- 空引用统一用 0 指针；每次解引用插入空检查，抛 `空指针异常`。

### 字符串

- 内部为 **UTF-16 码元数组 + 长度**，与 Java `String` 的 `length` / `取字符` / `取子串` 完全一致。
- 控制台与文件边界做 UTF-8 转换；Windows 启动时设置 UTF-8 代码页。
- 字符串拼接、插值、`空` 的打印在运行时统一处理，保证与 JVM 输出一致。

### 异常

- 一期用 `setjmp` / `longjmp` + 每线程异常处理器栈实现 `尝试` / `捕获` / `兜底`。
- 运行时维护函数符号表（函数名、源文件、行号），异常时打印中文栈。
- `声明抛出` 只做编译期标注，原生后端不强制检查。

### 内存回收

- 一期接入 **Boehm 保守 GC**；接口封装在 `运行时\gc.c`，后续可替换为自研标记-清除。
- M3 前允许临时 arena 分配，但必须在 M4 前切换到 GC。

## 理由

1. 与 JVM 的字符串索引、整数回绕、数组越界语义一致，才能做逐字节对拍。
2. UTF-16 内部表示避免每次 `取子串` 都做编码转换，边界只在 IO 处处理。
3. `setjmp` / `longjmp` 实现成本低，足以支撑一期异常；LLVM 展开留到二期。
4. Boehm GC 成熟、接入快，避免在语义尚未稳定时自研回收器。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| UTF-8 内部字符串 | `length` / `取字符` 与 Java 不一致，对拍成本高 |
| 引用计数 | 循环引用泄漏，且与 Java 语义不符 |
| 不回收（纯 arena） | 长循环内存增长，不能作为最终方案 |
| 自研标记-清除优先 | 一期风险高，留到 GC 语义稳定后 |

## 验收口径

- M4：09–21 课对拍一致，异常栈能定位到中文源行号。
- GC 压力用例（长循环创建对象与字符串）不崩溃、不出现明显泄漏。
- 空引用与越界用例抛出中文异常名，而不是段错误或英文系统错误。

## 影响

- 标准库的 C 实现必须复用同一套对象头、字符串与集合结构，不得各自定义私有布局。
- 任何改变对象头或字符串布局的改动都必须同步更新 C 后端、运行时与 GC。
