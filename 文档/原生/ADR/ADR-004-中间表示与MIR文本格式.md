# ADR-004 中间表示与 MIR 文本格式

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 5、6.3 节

## 结论

中间表示分两层：

1. **HIR**：带类型、已完成脱糖的抽象语法树。插值、`重复 N 次`、`否则若`、`入口`、切换表达式、自动装箱都在这一层消失。
2. **MIR**：控制流图 + 基本块 + 三地址码，类型收敛为 `i8 / u16 / i32 / i64 / f64 / ptr / struct`。

MIR 先定义**文本格式**，再实现**解释器**，最后才做代码生成：

- 每个函数一个 `func` 段，入口块固定为 `bb0`。
- 每条指令一行，采用三地址形式：`%t1 = add i32 %a, %b`。
- 基本块以 `br` / `condbr` / `ret` / `throw` 结束。
- 类型与字段布局显式打印，禁止依赖后端的隐式推断。
- 文本输出必须确定：同一输入多次生成的文本逐字节一致。

## 理由

1. 语义问题（装箱、求值顺序、异常路径）在解释器阶段暴露，比等代码生成后查汇编便宜得多。
2. MIR 文本可直接作为黄金快照，任何降级规则变化都会在 diff 中显形。
3. 控制流图与三地址码是 C 后端与 LLVM 后端的共同输入，避免为两套后端各写一遍降级。
4. 显式类型能提前发现 `i32` / `i64` 混用与有符号/无符号歧义。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| AST 直接生成 C | 前端与后端耦合，无法复用给 LLVM 后端，异常与控制流难表达 |
| 直接用 LLVM IR 作为唯一 IR | 一期没有 LLVM 后端，解释器与快照都难落地 |
| 栈式字节码 | 与「三地址 + 基本块」相比，后续优化与阅读成本更高 |
| 二进制 IR | 无法做黄金快照与人工审阅 |

## 验收口径

- M2：教程 01–10 在 MIR 解释器中的 stdout 与退出码和 JVM 后端一致。
- MIR 文本快照可重复生成，连续两次运行 diff 为空。
- 每个 MIR 函数的基本块都有唯一入口与显式终止指令，解释器对缺失终止指令报中文内部错误。

## 影响

- 后续所有优化（常量折叠、死代码删除）只改 MIR，不改前端与后端。
- MIR 文本格式一旦被快照引用，修改必须同步更新快照并在提交说明中注明。
- 浮点常量在 MIR 文本中使用可回读的十进制表示，避免精度丢失。
