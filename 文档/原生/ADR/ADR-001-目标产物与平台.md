# ADR-001 目标产物与平台

- 状态：已接受（M0）
- 日期：2026-11-09
- 关联：路线图第 1、2、14 节

## 结论

原生后端的一期产物是 **Windows x64 本机可执行文件（PE，`.exe`）**：单文件、双击可运行、运行时不依赖 JVM 或 JDK。

- 目标三元组：`x86_64-w64-windows-gnu`
- 链接器：`C:\msys64\mingw64\bin\clang.exe`（MSYS2 MinGW-w64）
- 一期只承诺静态链接到 libc 与运行时（`-static`），不承诺跨平台产物
- `.class` 继续保留，作为参考实现与对拍基准，不删除

## 理由

1. 仓库现有用户与教程都在 Windows 上，exe 是「双击就能运行」最直接的定义。
2. MinGW-w64 工具链已在本机验证：`clang 23.1.5`、`gcc 16.2.0`、`lld`、binutils 可用；`-static` 产物约 69 KB，能独立运行。
3. 先固定一个平台能把「对象模型、异常、字符串、GC」的语义问题收敛，避免一开始被三套 ABI 拖散。
4. 架构上仍把平台相关代码限制在 `原生\运行时\` 与 `原生\后端C\`，为后续 ELF / Mach-O 留接口。

## 替代方案

| 方案 | 不采用的原因 |
| --- | --- |
| 只产出 `.class` | 仍需 JVM，未达到「二进制可执行文件」目标 |
| GraalVM native-image | 复用 JVM 链路，无法按中文语义定制，报错仍来自 Java 工具链；仅作演示 |
| Linux ELF 优先 | 与现有教程运行环境不一致，验收成本高 |
| MSVC 工具链 | 本机未安装，且 `#line`、UTF-8 源文件与静态链接行为需额外适配 |

## 验收口径

- M3 起，`.\cjc.ps1 原生 编译 教程\第01课你好世界.java -o 构建\原生\第01课.exe` 产出 PE 文件。
- 生成的 exe 在无 JDK 的 PATH 下可直接运行，退出码与 JVM 后端一致。
- `dumpbin` 或 `objdump -f` 可识别为 `pei-x86-64`（工具缺失时以运行结果为准）。

## 影响

- 运行时与 C 后端不得依赖 POSIX 专有接口；文件、控制台、时间等按 Windows 先行实现。
- 跨平台相关代码必须集中隔离，避免在 MIR 与前端中出现平台判断。
- 文档中的命令统一使用 PowerShell 与绝对路径探测，不假设 clang 已在 PATH。
