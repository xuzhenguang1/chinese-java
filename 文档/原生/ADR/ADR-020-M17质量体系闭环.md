# ADR-020：M17 质量体系闭环（模糊测试 + 内存检查 + 双矩阵 CI + 白名单治理）

- 状态：Accepted（2026-11-22 方案拍板；分两批实施，验收见 `文档/原生/M17/`）
- 日期：2026-11-22
- 关联：路线图第 8 节、ADR-008（测试与对拍策略，本 ADR 修订之）、ADR-007（差异白名单与锚点）、后续路线计划书第 5 节、用户 2026-11-22 决策 E1/E2/E3/E4 + 历史 D3
- 前置：M16 已完成并推送（`d2015e9`），浮点/集合口径已冻结

## 背景

路线图第 8 节承诺的模糊测试、Linux 内存检查、跨平台 CI 三项，此前随 M0 写入 ADR-008 但一直未落地：ADR-008:14-17 只写了方向，验收口径 `:47` 仍停在 "M3 起 Windows/Linux 各跑 01–08 课"。ELF 运行器（M14）与语义冻结（M16）到位后，第一次具备可执行条件。

现状核查（2026-11-22）发现三处必须处理的约束：
1. **musl 全静态 + 自建 GC**：运行时所有堆分配经 `cjk_gc_alloc`（`cjkrt.h:7`、`gc.c:1-6`），不经 malloc；musl 全静态下 ASan 的 `__asan_init`/拦截器可用性与 GC 对象池 redzone 化均无保证。
2. **CI 硬阻塞**：`运行器.ps1:57-58` 与 `运行VM.py:13-15` 硬编码 `E:\cjk-qemu`/`E:\cjk-alpine` junction，Linux runner 上不存在；`检查调试信息Linux.ps1:15` 硬编码 Windows readelf。
3. **资产无校验依据**：M14 报告只记了 qemu 装包 SHA512，内核/rootfs/musl 缺 SHA256；二进制资产按 `.gitignore:2` 不入库。

用户 2026-11-22 四项决策（E1–E4）如下，历史 D3（CI 跑 ELF 全量对拍）不变。

## 决策

### 1. 模糊测试：健壮性三断言，不做输出对拍

- 新增 `原生/测试/模糊.ps1`，Token 池复用 `关键字表.txt` / `近义词典.txt` / `方法糖.txt` 的中文侧键，固定种子保证可复现。
- 三条断言：① 不崩溃（前端退出码在已知集合 0/1/2，非异常终止）；② 不挂起（单轮固定超时）；③ 中文诊断（stderr 命中已知 `CJK\d{3}` 或中文提示，裸英文异常栈判失败）。
- **不做输出逐字节对拍**：随机输入无期望输出，只做健壮性断言。
- 失败样本落 `构建/模糊失败样本/`（不入库），含种子/轮次/token/stderr，可复现。
- 诊断命中 `差异白名单.txt` 条目时，须其 `ADR-007:` 锚点在 ADR-007 正文存在（E1 之外的白名单治理接入）。

### 2. 内存检查：ASan 优先 + 实测降级阶梯（E1）

- 驱动 `驱动.ps1` 新增 `-内存检查` 开关，与 `-无缓存/-优化/-平台/-清单` 正交，**仅在 `-平台 linux` 生效**；注入 ASan 编译/链接参数，并**并入 `取工具链哈希`** 隔离缓存分桶。
- **断言不可写成"必须 ASan"的硬门槛**。按以下阶梯实测降级，每级触发条件与结论记录在本 ADR：

| 阶梯 | 触发条件 | 断言口径 |
| --- | --- | --- |
| A. musl 静态 ASan | 全静态 + ASan 能链接、`__asan_init` 成功、注入已知内存错误能被捕获 | ASan 报告无 leak/overflow |
| B. Clang 静态分析 | A 链接/运行失败（记录具体错误） | `-fanalyzer` / `scan-build` 无告警 |
| C. ASan + GC poison 钩子 | A 可用但因 GC 对象池不经 malloc 致检测失效，且 `cjk_gc_alloc` 加 `__asan_poison_*` 风险可控 | 同 A，且钩子不改变非 ASan 构建 |
| D. valgrind | A/C 均不可行，且能提供动态 musl 构建路径 | valgrind 无 leak/overflow |

- `内存检查Linux.ps1` 复用 GC 四组 + 第 20/21 课异常 + 第 27 课文件 IO + 网络冒烟，走 `运行器.ps1 -平台 linux`，解析 `.elf.out/.exit`。
- **最终采用哪一级、为何降级，实施后在 `文档/原生/M17/对拍报告.md` 与本 ADR 记录**，不以"应该能用 ASan"作为验收前提。

### 3. 双矩阵 CI：CI 覆盖 ELF 全量对拍（D3 不变）

- `校验.yml` 扩 `strategy.matrix`：windows-latest + ubuntu-latest，JDK 25（temurin）。
- Windows job：保持现有 `校验.ps1`（非原生全量）不变。
- Ubuntu job：apt 装 qemu-system-x86/python3 → 下载 Alpine 内核/rootfs/musl（按 M14 报告新增 SHA256 校验表）→ Actions cache `构建/工具链/` → 复用 `构建initramfs.py`/`运行VM.py`/`对拍ELF.ps1` 跑 ELF 全量对拍（35 课 C/LLVM、示例工程、自举不动点、DWARF、GC、网络冒烟）。
- **实施口径修正**：两个 job 的 `校验.ps1` 均不带 `-含原生`——原生补丁回归依赖 JDK 内部 `src.zip`，沿用原 CI 口径留在本地；原生质量网由本地 `校验.ps1 -含原生` 与上述 ELF 全量作业共同覆盖。
- **资产策略（E2）**：现场下载 + Actions cache，二进制不入库；下载后按 M14 报告 SHA256 校验，cache key 含资产版本。
- **DWARF（E3）**：`检查调试信息Linux.ps1` 的 readelf 路径改为可配置（环境变量/参数），CI 用系统 readelf、本机回退原 Windows 路径，零回退。
- **CI 与本机共脚本**：`运行器.ps1:57-58` 与 `运行VM.py:13-15` 的 E: 硬编码路径改为 `CJK_QEMU`/`CJK_ALPINE`/`CJK_KERNEL` 环境变量覆盖，未设时回退原值（本机零回退）。
- CI 只做功能对拍，不复现本机性能基线；设 job 级 `timeout-minutes` 与单课超时，串口日志保留用于定位。

### 4. 白名单治理自动化

- M16 建立的锚点可追溯机制（白名单每条 + 浮点已知差异每条 → ADR-007/ADR-020 锚点）纳入 `校验.ps1` 8.16 与模糊断言。
- 8.16 追加：文件清单、ADR 计数 20、模糊脚本 CJK 断言文本、锚点可追溯复用。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| ASan 硬门槛（不可降级） | 未采纳（E1） | musl 静态 + 自建 GC 可行性无保证，硬门槛会让 CI 永久红 |
| 直接 valgrind / 只做静态分析 | 未采纳（E1，作为降级后备） | 先实测 ASan；不行再按阶梯降级，避免未实证就放弃最强检测 |
| 二进制资产提交入库 | 未采纳（E2） | `.gitignore:2 构建/` 惯例；体积大；改为下载 + cache + SHA256 校验 |
| CI 跳过 DWARF | 未采纳（E3） | 可配置 readelf 成本更低且覆盖完整，本机零回退 |
| 一次全量交付 | 未采纳（E4） | 分两批：本机质量网可独立提交，CI 前置本地模拟通过，问题易定位 |
| ELF 对拍留本机 | 未采纳（历史 D3） | 用户已拍板 CI 跑 ELF 全量 |

## 验收

1. 模糊固定种子 N 轮：无崩溃、无挂起、诊断中文且命中已知码；失败样本可复现。
2. 内存检查按 E1 当前阶梯跑通 GC 四组 + 异常 + 文件 IO + 网络冒烟；对应工具无 leak/overflow；降级原因与边界记录在本 ADR 与对拍报告。
3. 双矩阵 CI 两 job 均绿；ubuntu job 完成 ELF 全量对拍（35 课 C/LLVM + 示例工程 + 自举不动点 + DWARF + GC + 网络冒烟）。
4. 35 课、快照、自举不动点零回退；`校验.ps1 -含原生` 新增 8.16 后退出码 0；ADR 计数 20。
5. CI 与本机共用打包/VM/对拍脚本，资产版本与 M14 报告一致（含新补 SHA256），无口径漂移。
6. 本机零回退：E3 可配置 readelf 未设环境变量时行为不变；路径参数化后本机 E: junction 照常工作。
