# ADR-023：M20 运行时二期范围（浮点根治 · 泛型单态化 · 双后端 DWARF 异常展开）

- 状态：Accepted（2026-11-24 用户拍板 G4/G5/G6）
- 日期：2026-11-24
- 关联：后续路线计划书-M19至M22 第 4 节、ADR-006（运行时与对象模型：异常与泛型口径）、ADR-007（语义兼容与浮点已知差异）、ADR-009（LLVM 后端调试信息）、路线图第 6 节二期项
- 前置：M19 符号冲突根治已交付并推送（06de551），双矩阵 CI 全绿，35 课四路对拍 + 快照 + 自举不动点零回退，ADR 22 份，校验节 8.0–8.18

## 背景

M0–M18 的运行时是「一期能用」口径：异常用 `setjmp`/`longjmp`（ADR-006），泛型走擦除装箱（`cjk_object*` 值盒），浮点最短表示在 M16 边界实证中对次正规数登记了唯一一处「已知差异」（ADR-007 已知限制第 2 条）。路线图第 6 节把「异常升级 DWARF 展开、泛型按需单态化、浮点移植 Ryu/ FloatingDecimal 级算法」列为二期项，本 ADR 兑现这三项。

**2026-11-24 开工前对齐**，用户拍板三项决策（计划书 §7.2 的 G4/G5/G6）：

- **G4**：泛型单态化若实测必须改 MIR 文本，**预授权冻结基线重生成**（沿用 M18 F3-A：冻结旧副本 + A/B 双实现交叉确认），不中途另立决策。
- **G5**：DWARF 异常展开 **C/LLVM 双后端都改**，不再保留「仅 LLVM 启用、C 保留 setjmp」的双轨口径。这是对原计划书 §4.1/§4.3/§4.5 的推翻。
- **G6**：浮点根治**做**，推翻 M16「已知限制不修」结论，消除 `Double.MIN_VALUE` 次正规数差异。

## 决策

### 1. 推进顺序（风险递增，硬约束）

三块按 **浮点根治 → 泛型单态化 → DWARF 异常展开** 顺序推进，**前一块零回退后才动下一块**。理由：DWARF 双后端都改（G5）会变动 C 后端异常 ABI，波及 M16 已验证的异常/栈回溯用例，是风险最高的一块，必须在前两块确认稳定、且有一个干净的回退基线后再动。

### 2. 浮点根治（G6）

- **根因**：`原生/运行时/cjkrt.c:417-426` 的 `格式化浮点()` 从 `p=0` 递增找「`%.pe` 回读等于原值」的最短位数即停。`Double.MIN_VALUE`（1 ULP，`4.9e-324`）在 `p=0` 时 `%.0e` 得 `5e-324`，`strtod` 回读恰等于该 ULP，于是停在 1 位有效数字；Java `FloatingDecimal` 要求「最短且能唯一区分相邻 double」，1 位 `5e-324` 的舍入区间覆盖多个 double，故取 2 位 `4.9E-324`。相邻 2 ULP 同理（`1.0E-323` vs `9.9E-324`）。
- **修复方向**：对 `p` 找到的候选十进制，验证其是否**唯一回读**到原 double——即不存在另一个 double 也能由该十进制按同一规则回读；若不唯一则提高 `p` 继续，直到满足。等价于 Java `FloatingDecimal` 的 `dtoa` 规则。实现限定在 `格式化浮点()` 内，不引入完整 Ryu 表（保留现有 snprintf 回读骨架，只把「可回读即停」收紧为「唯一可回读才停」）。
- **口径不变项**：NaN/Inf/±0、十进制区间 `[-3,6]` 的非科学计数显示、`%f`（`%.6f`）独立路径、单精度 `float` 分支——均不动。每改一步跑浮点边界 7 例（浮1–浮7）+ 35 课，任何正常值回退即判 bug。
- **登记撤销**：实测 7/7 无「已登记差异」且 `浮5` 的 MIN_VALUE 与 Java 逐字节一致后，撤销 `原生/测试/浮点已知差异.txt` 的 `^minvalue=.*` 行、删除 ADR-007「已知限制」第 2 条（`ADR-007:浮点边界` 锚点），并把 ADR-007 语义点表「浮点打印」行更新为「根治完成、无已知差异」。**差异未真正消除前不得撤销登记**，不以归一化掩盖回归。
- **ADR-007 随机源限制第 1 条不动**（随机整数白名单与本决策无关）。

### 3. 泛型单态化（G4）

- 在 C/LLVM 后端对 `cjk_object*` 值盒按实参类型生成特化版本（如 `cjk_list_int32` / `cjk_list_object`），保留 `__值` 的 MIR 文本表示不变；对拍验证特化后输出与擦除版逐字节一致。
- **MIR 文本不改**是承诺：单态化限定在后端类型特化层，不改 MIR 降级输出、不改 105 份 AST/MIR/语义快照。
- 若某泛型形态特化成本过高（如递归/自引用泛型、边界擦除场景），保留擦除回退并在本 ADR 的「已知限制」说明该形态与判定条件，不强行特化。
- **G4 授权**：若实测必须改 MIR 文本，按 M18 F3-A 冻结旧副本 + A/B 双实现交叉确认重生成基线，不中途回用户对齐。变更记入 M20/对拍报告.md 的基线迁移节。

#### 3.1 落地调研与最终决策（2026-11-24）

开工实测（T2）后确认两点架构事实，据此收敛落地路径：

1. **值盒池化（曾考虑的低成本方案）不可行**：`原生/运行时/gc.c` 是纯保守标记-清除，无回收回调 / 弱引用 / 空闲块复用；池一旦持有盒引用即永久存活，反而加重 GC 压力。`cjk_box_value`（`值.c:214`）对基本类型每次 `gc_alloc(sizeof(cjk_box))`——这是自定义泛型类字段装箱开销的真实来源，但无法用池化消除。
2. **MIR 类定义体已擦除**：语义分析器 `转类型`(:3207) 把类型变量 `T` 擦除为 `__值`（`字段 __值 内容`、方法签名 `__值`），仅变量声明/读取处经 `类型.实参` 保留实参（`盒子<文本>`）。故"按实参特化类定义"要求后端做实例敏感分析 + 方法克隆 + 按接收者实参路由，C/LLVM 双份对称。

**用户 2026-11-24 最终决断：坚持完整单态化**（放弃热点直连优化与跳过两选项）。执行口径：按实参实例为自定义泛型类生成特化结构体（`__值` 字段→具体类型）+ 特化方法 + 调用路由；多态/接口/继承场景逐个击破；若某形态确实无法对齐，按上述"成本过高保留擦除回退"条款在该形态上回退并记入 M20/对拍报告.md，不影响已特化形态。推进时以 35 课对拍 + 105 快照零回退为硬门槛，能力层用后端单测证明特化生效。

### 4. DWARF 异常展开（G5，双后端都改）

- **LLVM 后端**：异常路径生成 `landingpad`（Itanium ABI personality）替代 `longjmp`；`cjk_frame` 帧链保留供中文栈回溯（DWARF 只负责控制流，中文帧名仍由运行时打印）。现有 `DISubprogram`/`DILocation` 元数据（ADR-009）沿用，不重做调试信息。
- **C 后端（G5 新增改造点）**：与 LLVM 对称地生成展开 landing 逻辑 + personality 调用，共同替代 `setjmp`/`longjmp`。C 后端异常 ABI（`jmp_buf` 探针 200 / handler 216）**不再是冻结项**，随展开改造调整；ADR-006「异常」节由「一期 setjmp」更新为「二期 DWARF 展开 + 中文帧链」。
- **双后端统一口径**：不再双轨。异常用例（第 20/21 课）C/LLVM/JVM 三方逐字节一致，中文栈帧定位正确。M16 已验证的异常/栈回溯用例全量重跑，零回退。
- **回退路径**：单轨化后不再有 setjmp 回退路径。若 C 侧展开无法与 JVM 对齐，**不自动降级为双轨**，须回到用户重新对齐再决策。

### 5. 双后端 ABI 与运行时约束（不变项）

- 不改对象头 / 数组布局 / UTF-16 字符串表示（ADR-006 其余部分不动）。
- 不改 M19 符号编码算法（ADR-022 冻结），本里程碑不得改任何符号编码调用点与别名逻辑。
- 不引入 Rust 后端、不做 LTO/-march（M12 已测无收益）。

## 回滚预案

- 三块各自独立提交：阶段 0（ADR）→ 阶段 1（浮点）→ 阶段 2（泛型）→ 阶段 3（DWARF）→ 阶段 4（校验 + 文档）。任一块失败 `git revert` 该阶段提交即可，前序块基线干净。
- 浮点根治若破坏正常值最短表示：回退 `格式化浮点()` 改动，登记撤销动作随之回退。
- 单态化若触发 MIR 文本变化：按 G4 授权先冻结旧副本再重生成，原基线副本保留只读对照。
- DWARF 双后端改造若三方对拍无法一致：回退该阶段提交（回到 setjmp 基线），并回用户重新对齐——**不自动降级为双轨**。
