# ADR-019：M15 范围（包管理：本地清单 + 离线依赖 + 双轨构建）

- 状态：Accepted（2026-11-21 方案拍板；实施与验收见 `文档/原生/M15/`）；**2026-11-25 M21 修订**：§2「版本精确相等、范围与冲突求解明确不做」与备选方案表「远程 registry + semver 未采纳（D2）」已被 [ADR-024](ADR-024-M21平台与生态范围.md) 的 G8「含远程下载」决策推翻——M21 在中文 DSL 基础上扩展 semver 范围、本地 registry 与远程下载；下方历史原文保留作 M15 一期追溯。
- 日期：2026-11-21
- 关联：路线图 ADR-010:47-55（包管理延后）、ADR-017:25（包管理顺延 M15）、ADR-013/014/015（多文件前置）、M13 spec:74-80、用户 2026-11-21 决策 D1/D2、ADR-024（M21 修订本文 D2）

## 背景

ADR-010 当初否决包管理的理由是"原生前端只做单文件语义；远程依赖解析引入版本求解与网络，收益不足"，并规定启动前须先解决多文件语义与平台抽象。这两块前置已由 M13（多文件模块，两阶段共享类表）与 M14（平台抽象 + 交叉工具链）完成并推送，全量校验退出码 0。ADR-017 据此把原 M14 包管理正式顺延为 M15。

2026-11-21 用户决策（D1/D2）：清单用**中文 DSL**（不用 JSON）；一期依赖来源为**本地路径 + 精确版本**，不做远程 registry 与 semver 范围求解。

## 决策

### 1. 清单格式：中文 DSL，唯一格式

新增 `依赖清单.txt`（UTF-8，允许 BOM），每行一条指令，`#` 开头为注释。五个指令：

```
包名 演示.应用
版本 1.0.0
入口 src/main/中文/演示/应用/主程序.java
源目录 src/main/中文
依赖 工具库 路径 ../公共库 版本 1.2.0
```

BNF（`WS` 为一个或多个空白）：

```
清单     := 行*
行       := 空行 | 注释 | 指令
注释     := "#" 任意字符*
指令     := "包名" WS 包全名
         | "版本" WS 版本
         | "入口" WS 路径
         | "源目录" WS 路径
         | "依赖" WS 名称 WS "路径" WS 路径 WS "版本" WS 版本
版本     := 数字 ("." 数字)*        # 精确匹配，不做范围
路径     := 非空白字符+             # 相对清单文件所在目录解析
```

基数：`包名`/`版本`/`入口` 恰好 1；`源目录` ≥1；`依赖` 0..n。解析器落在 `工具/cjc/依赖清单.java`（默认包，与 `Cjc.java` 同目录，source-file 模式可直接运行）。

**JSON 方案作废，不留双解析器**；格式若需变更，先修订本 ADR 再改代码。

### 2. 依赖解析：本地路径 + 精确版本，离线闭环

- `依赖 名称 路径 <路径> 版本 <版本>` 的路径相对当前清单目录解析；读取被依赖包的 `依赖清单.txt`。
- 版本**精确相等**才通过；范围与冲突求解明确不做（非目标）。
- 以 `包名` 去重：同名同版本跳过，同名异版本报版本冲突。
- 以规范化绝对路径做递归栈查环；被依赖清单不存在报缺失清单。
- 输出有序源文件列表：主工程优先，依赖按 DFS 顺序，去重并保留唯一入口，交给 M13 既有的 `分析模块(单元们, 入口文件名)`，**不另造源文件收集器**。

四类依赖错误 + DSL 语法错误均给中文诊断、退出码 2、含路径上下文：循环依赖、缺失清单、版本冲突、重复包；未知指令 / 参数不符 / 缺单值指令 / 重复单值指令 / 版本格式非法。

### 3. 缓存：清单变化必须击穿

- `驱动.ps1` 的 `取工具链哈希` 并入主清单与闭包内所有被依赖清单的内容哈希。
- 编译分支的聚合源哈希追加所有清单文本哈希；状态 JSON 增 `依赖哈希` 字段并参与命中。
- 以两条反向用例强制验证：改依赖声明（不改源码）必重编；依赖与源均未变必命中缓存。

### 4. 双轨并存：原生清单与 Maven 互不覆盖

- `新建 项目` 同时生成 `依赖清单.txt`、`构建.ps1`（原生双轨）、`pom.xml`（JVM 路径），互不解析、互不覆盖。
- `构建.ps1` 用 `cjc.ps1 依赖 解析` 读清单 → 得出源文件列表 → 调 `原生 编译 <多源...>`，走 M13 `编译模块` 共享分析；不再写死单文件。
- 不改 JVM/Maven 链路语义，不改 35 课源文件、AST/MIR/语义快照、自举不动点、`编码()`。

### 5. 命名规避

清单"依赖包"（分发单元）、语法 `包 演示.应用;`（命名空间）、第 22 课「清单 = ArrayList」（集合类）三者同名不同义，本 ADR 明确定义，文档避免混用。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| JSON 清单 | 未采纳（D1） | 用户选中文 DSL；全仓中文命名，DSL 与诊断风格一致 |
| 远程 registry + semver 求解 | 未采纳（D2，M15 一期）；**2026-11-25 M21 G8 推翻，改为采纳** | M15 一期最小闭环；求解器与网络收益不足后置。M21 按 ADR-024 G8 扩为 semver 范围 + 本地 registry + 远程下载 + 缓存 |
| 另造源文件收集器 | 未采纳 | M13 `分析模块` 已提供成型入口，复用降低漂移风险 |
| 清单取代 pom.xml | 未采纳 | 双轨并存，JVM 路径至少一个版本内保留（ADR-010 影响节口径） |

## 影响

- 35 课对拍、AST/MIR/语义快照、自举不动点、DWARF/基准均不得变化；`校验.ps1` 新增 8.14，ADR 计数 18 → 19。
- 清单是纯构建期输入，不进入语言语义、不影响 JVM 后端。
- `依赖 解析|哈希` 由 `cjc.ps1` 顶层识别首参后直接转发到 `依赖清单.java`（source-file 模式），不进 `Cjc.java`，既有命令路径零改动；解析结果支持写入 UTF-8 文件中转，规避 Windows PowerShell 5.1 捕获 java stdout 的中文路径误解码。

## 验收

1. `cjc.ps1 依赖 解析 <清单>` 输出入口 + 有序源文件列表，退出码 0；语法/依赖错误给中文诊断、退出码 2。
2. 示例工程 10 源清单驱动 C/LLVM/JVM 三方逐字节对拍一致；二级本地依赖样例闭包正确。
3. 改依赖必重编、无变化必命中两条反向用例通过。
4. `新建 项目` 生成三件套，`.\构建.ps1` 一条命令产出可运行 exe，Maven 路径不回退。
5. Windows PE 与 Linux ELF 双平台清单构建通过；`.\工具\发布\校验.ps1 -含原生` 退出码 0。
