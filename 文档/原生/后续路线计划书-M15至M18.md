## 1. 总览：为什么按 M15 → M16 → M17 → M18 排

四个方向不是并列关系，存在三条硬依赖，因此**不按选择顺序平铺**，而按依赖链编排：

```
M15 包管理 ──(清单即源文件列表)──┐
                                  ├→ M17 质量体系 ──(保护网)──→ M18 跨文件自举
M16 语义实证 ──(冻结浮点/集合口径)┘                              ↑
                                                     (最敏感基线最后动)
```

| 顺序 | 里程碑 | 排序依据 |
| --- | --- | --- |
| M15 | 包管理（本地清单 + 离线依赖 + 双轨构建） | 路线图/ADR-017 明确顺延的下一站；前置（多文件语义 + 平台抽象）已就绪；产出"源文件列表"正好是后续两阶段的通用输入格式 |
| M16 | 语义兼容实证（浮点 + 无序集合口径冻结） | 工作量小、风险低；**必须先冻结口径**，否则 M17 模糊测试一旦失败无法归因到"实现 bug"还是"已知差异" |
| M17 | 质量体系闭环（模糊 + ASan + 双矩阵 CI + 白名单治理） | 建立自动化保护网；M18 要动自举基线，必须在保护网就位之后进行 |
| M18 | 跨文件自举不动点（自举六期） | 改动面最大、最容易动摇已冻结的 35 课快照与 175 组不动点；放最后，用前三个里程碑的保护网兜底 |

### 1.1 核查修正：方向④的重新定性

原设想是"移植 Ryu、清零白名单"，现场核查后发现前提不成立：

- `原生/测试/差异白名单.txt` 全文只有 3 行——2 行注释 + 1 条正则 `^随机整数：-?\d+$`。ADR-007 最初登记的"浮点末位""无序集合顺序""默认哈希码"三条豁免**早已收敛删除**。
- `原生/运行时/cjkrt.c:399-481 格式化浮点(...)` 不是查表 Ryu，而是用 `snprintf("%.*e")` 从 p=0 递增找"strtod/strtof 可回读"的最短位数，再规范化成 Java 风格十进制/科学计数法（指数区间 -3..6）。
- `原生/运行时/集合.c` 的 `cjk_seq`/`cjk_map` 都是**插入序**平行数组，不是哈希序；哈希只用于等值去重。

因此 M16 不是"清零白名单"，而是**"给既有实现做边界实证、把结论冻结进 ADR"**——工作量显著小于原设想，且恰好构成模糊测试的前置。

### 3.3 核心设计

**清单文件**（已按 D1 定为**中文 DSL**，不采用 JSON；文件名建议 `依赖清单.txt` 或 `依赖.清单`，与全仓中文命名一致）：

```
包名 演示.应用
版本 1.0.0
入口 src/main/中文/演示/应用/主程序.java
源目录 src/main/中文
依赖 工具库 路径 ../公共库 版本 1.2.0
依赖 数据工具 路径 ../数据工具 版本 2.0.0
```

- DSL 语法：`包名` / `版本` / `入口` / `源目录` / `依赖` 五个中文指令，每行一条；`依赖` 后接 `名称 路径 <值> 版本 <值>`。注释行以 `#` 开头。
- 解析器落地在 Java 侧（`Cjc.java` 或新 `依赖清单.java`），复用现有词表/诊断基础设施；解析错误给中文诊断（未知指令、缺参数、重复键、版本格式错）。
- 依赖来源一期只认**本地路径**（相对清单文件解析，D2），递归读被依赖包的清单。
- 版本一期只做**精确匹配**（相等即通过），不做范围求解；不满足给中文诊断。
- 解析产物是有序、去重的源文件列表 + 唯一入口，喂给 `分析模块程序`。
- 循环依赖、缺失清单、版本冲突、重复包四种错误给中文诊断（复用现有诊断框架，必要时扩展 CJK 码段）。
- **命名规避**：清单里的"依赖包"是分发单元，语法里的 `包 演示.应用;` 是命名空间，文档中明确区分，避免与第 22 课「清单 = ArrayList」混淆。
- **回退口径**：DSL 的 BNF 与示例必须写进 ADR-019 后再实现，避免格式漂移；JSON 方案作废，不留双解析器。

## 4. M16 语义兼容实证（浮点 + 无序集合口径冻结）

### 4.1 目标 / 非目标

**目标**：建立浮点打印的边界对拍集，实证 `格式化浮点()` 与 Java `数值.转文本`（`标准库/src/main/java/中文/标准库/数值.java:15-16` 的 `String.valueOf`）在 35 课之外的一批边界值上是否逐字节一致；把结论（一致范围 / 需登记的豁免 / 不可比的白名单）固化进 ADR-007 与白名单治理流程。

**非目标**：

- 不做 Ryu 全量移植（现有实现已是"可回读最短表示"，先实证再决定是否值得改）。
- 不改集合遍历顺序（现为插入序，属正确行为）。
- 不新增 ADR 编号，只修订 ADR-007。

### 4.2 现状切入点

| 位置 | 现状 |
| --- | --- |
| `原生/运行时/cjkrt.c:399-481` | `格式化浮点(...)`：特殊值 `:400-410`，snprintf 最短回读 `:414-424`，Java 风格规范化 `:447-478` |
| `原生/运行时/值.c:229-249` → `标准库.c:140-183` | `cjk_value_to_string` → `cjk_output_format`；`%f` 固定 `%.6f` 在 `:178`（对齐 Java `Formatter` 的独立语义） |
| `标准库.c:1380-1410` | JSON 输出对浮点先判 NaN/Inf 再走同一函数 |
| `原生/运行时/集合.c:33-38,470-477,506-516` | 插入序平行数组；`cjk_value_hash` 在 `值.c:312-337` 只用于去重 |
| `文档/原生/ADR/ADR-007` | 语义点表列"浮点打印""无序集合遍历"；初始豁免 1–3 已删除 |

### 4.3 核心设计

- **边界用例集**：±0.0、NaN、Infinity、最大/最小正规数、次正规数、1e-7 / 1e7 边界、`2^53`、15/16/17 位有效数字、舍入临界值、科学计数法指数边界 −3..6。
- **新增 `原生/测试/对拍浮点.ps1`**：同一批值分别走 JVM `数值.转文本` 与原生 `输出`/`数值.转文本`，逐字节比较；沿用 `对拍.ps1:20-54` 的路径收集与归一化骨架。
- **差异处置分层**：能在 `格式化浮点()` 内小改修好的就修；涉及 Ryu 全量移植的差异登记为 ADR-007 已知限制，不进白名单（白名单只放真正不可比项）。
- **无序集合结论固化**：在 ADR-007「无序集合遍历」条目写明原生为插入序、对拍统一用 `链式键值表`，`HashMap` 顺序不纳入逐字节断言；不新增白名单条目。
- **白名单治理静态检查**：白名单每条必须能指到 ADR 具体条款；`校验.ps1` 增加该检查，为 M17 的 CI 接入做准备。

### 5.3 核心设计

**模糊测试** `原生/测试/模糊.ps1`：

- 复制 `对拍.ps1` 的"路径列表 + 归一化 + 逐字节比较"骨架，输入改为随机 Token 序列（复用词表）。
- 断言三条：不崩溃、不挂起（固定超时）、诊断是中文且命中已知 CJK 码。
- 固定种子保证可复现，失败样本落盘到 `构建/模糊失败样本/`（构建产物，不提交）。
- 不做输出逐字节对拍（随机输入无期望输出），只做健壮性断言。

**内存检查** `原生/测试/内存检查Linux.ps1`：

- 驱动新增 `-内存检查` 旗标（与 `-无缓存` 正交），给 clang 追加 ASan 编译/链接参数。
- 走现有 `运行器.ps1` + Alpine VM，跑 GC 压力 4 组 + 第 20/21 课异常 + 第 27 课文件 IO + 网络冒烟。
- 收集 ASan 报告并断言无 leak / overflow；musl 静态 ASan 支持需实测，若受限则回退到 valgrind 或 Clang 静态分析，并在 ADR-020 记录边界。

**双矩阵 CI** `.github/workflows/校验.yml`（按 D3：CI 跑 ELF 全量对拍）：

- 扩为 `strategy.matrix`：`windows-latest` + `ubuntu-latest`，JDK 25。
- CI 范围：非原生全量校验 + 原生静态可编译检查（`javac` 全量 + `原生 检查 教程` 35/35）+ **ELF 全量对拍**（35 课 C/LLVM、示例工程、自举不动点、DWARF、GC、网络冒烟）。
- **CI 内的 ELF 运行资产**：ubuntu job 用 apt 安装 `qemu-system-x86_64`；从 Alpine CDN 下载与本机同版本的 `linux-virt` 内核与 `minirootfs`，用仓库内 `原生/测试/工具/构建initramfs.py` 打包 initramfs，用 `运行VM.py` 启动并捕获串口。资产版本、URL、SHA256 固化在 `M14/工具链与ABI探针报告.md`，CI 与本机共用同一套脚本，避免两套口径漂移。
- 工具链：ubuntu job 用 musl.cc 或 Alpine 包源获取与本机同版本 musl sysroot（已在 M14 报告记录）；若 CI 下载超时，允许用 GitHub Actions cache 缓存 `构建/工具链/`。
- **超时与熔断**：VM 批量对拍按课分批执行，单课超时上限写进 `运行VM.py`；CI job 设 `timeout-minutes`，避免 VM 卡死拖垮整个矩阵。
- 本地先用相同命令模拟 Linux job 跑通（含 VM 启动），再提交 CI 配置。
