## 1. 目标

给中文工程引入**依赖清单 + 本地包解析**，使 `新建 项目` 产物与多文件工程能声明依赖、离线解析、一条命令构建；源文件、依赖、工具链任一变化都能正确触发重编。

### 非目标

- 不做远程仓库下载、registry、完整 semver 求解（后置，另立 ADR）。
- 不改 JVM/Maven 链路语义；原生清单与 `pom.xml` 并存、互不覆盖。
- 不改 35 课源文件、AST/MIR/语义快照、自举不动点文本、`编码()`。
- 不改 Windows PE / Linux ELF 的 ABI 与运行时。

## 3. 核心设计

### 3.1 清单文件格式（D1：中文 DSL，不用 JSON）

文件名 `依赖清单.txt`，UTF-8（允许 BOM），每行一条指令，注释以 `#` 开头。五个指令：

```
包名 演示.应用
版本 1.0.0
入口 src/main/中文/演示/应用/主程序.java
源目录 src/main/中文
依赖 工具库 路径 ../公共库 版本 1.2.0
```

| 指令 | 参数 | 基数 | 说明 |
| --- | --- | --- | --- |
| `包名` | 包全名 | 恰好 1 | 与源码 `包` 声明一致，作为依赖去重键 |
| `版本` | `主.次.修订` | 恰好 1 | 精确版本，不做范围 |
| `入口` | 相对清单的路径 | 恰好 1 | 传给 `分析模块(单元们, 入口文件名)` 的唯一入口 |
| `源目录` | 相对清单的路径 | ≥1 | 递归收 `*.java`，相对清单文件解析 |
| `依赖` | `名称 路径 <路径> 版本 <版本>` | 0..n | 本地路径依赖，版本精确匹配 |

- 解析器新增 `工具/cjc/依赖清单.java`，与 `Cjc.java` 同目录、同默认包（无 package 声明），由 Java source-file 模式直接运行；`cjc.ps1` 识别首参「依赖」后转发到它（不经 `Cjc.java`）。
- **中文路径编码口径**：Windows PowerShell 5.1 捕获 java stdout 会按 ANSI 误解码 UTF-8 中文路径，故 `依赖 解析 <清单> [输出文件]` 支持把结果写入 UTF-8 文件，所有调用方（构建脚本、对拍脚本、驱动哈希）统一读文件中转，不直接捕获 stdout。
- 数据类 `清单`：`包名 / 版本 / 入口 / 源目录们 / 依赖们`；`依赖`：`名称 / 路径 / 版本`。
- DSL 的 BNF 与上面五个指令示例**必须写进 ADR-019** 后才实现，避免格式漂移；JSON 方案作废，不留双解析器。
- 错误定性（全部中文，走 `Cjc.fail` 同款输出、退出码 2）：未知指令、参数个数不符、缺 `包名/版本/入口`、重复单值指令、版本格式非法。

### 3.2 依赖闭包解析（D2：本地路径 + 精确版本）

算法（在 `依赖清单.java` 内实现，供 CLI 与驱动调用）：

1. 解析主清单 → 得到 `{入口, 源目录们, 依赖们}`。
2. 深度优先遍历依赖：对每条依赖，按"相对当前清单目录"解析 `路径`，读被依赖包的 `依赖清单.txt`。
3. 校验被依赖包的 `版本` == 依赖行声明的版本；不等 → 版本冲突错误。
4. 以 `包名` 为键去重；同一 `包名` 第二次出现且版本一致 → 跳过；版本不一致 → 版本冲突错误。
5. 用「规范化绝对路径」集合检测环：递归栈里再次出现 → 循环依赖错误。
6. 叶子清单不存在 → 缺失清单错误。
7. 输出有序结果：`入口文件 + 所有源目录下的 .java（主工程优先，依赖按 DFS 顺序）`，去重后交给 `分析模块程序`。

四类依赖错误 + DSL 语法错误，全部中文诊断、可读、含路径上下文：

```
依赖清单缺失：<路径>（期望该目录下有 依赖清单.txt）
循环依赖：甲 -> 乙 -> 甲
版本冲突：依赖「工具库」要求 1.2.0，实际 2.0.0（<路径>）
重复包：包名「演示.工具」出现两次（<路径1>、<路径2>）
清单语法错误（<文件>:<行>）：未知指令「<词>」
```

### 3.3 缓存：清单与依赖变化必须击穿

- `取工具链哈希`（`驱动.ps1:153-171`）：追加"依赖清单内容哈希"——对主清单与闭包内每个被依赖清单的文本做 `取文本哈希` 后按序拼接。
- `编译` 分支（`:542-548`）：`$源哈希` 的聚合输入从"所有源文件哈希"扩展为"所有源文件哈希 + 所有清单文本哈希"，保证改依赖声明必重编。
- 状态文件（`:550`）：JSON 增 `依赖哈希` 字段，参与命中判定。
- 两条反向用例（写进 `对拍报告.md`）：① 改依赖声明（不改源码）→ 必须重编；② 依赖与源均未变 → 必须命中缓存输出"增量…跳过"。

### 3.4 CLI 与脚手架双轨

- **CLI**：`cjc.ps1 依赖 解析 <清单路径>`（Java 侧，输出解析后的源文件列表与入口，供人检查）；不新增 PowerShell 命令，构建走既有 `原生 编译 <多源...>`。
- **脚手架**：`createProject` 额外生成 `依赖清单.txt`；`nativeBuildTemplate` 改为：用 `cjc.ps1 依赖 解析` 读出源文件列表，再调 `& $cjc 原生 编译 @源文件 -o $输出`（多源走 M13 `编译模块`）。`pom.xml` 原样保留，双轨互不覆盖。
- **示例工程**：手工补 `依赖清单.txt`（3 包 10 源、`源目录 src/main/中文`、入口 `演示/应用/主程序.java`），作为对拍样本；不改造 Maven 路径。

### 3.5 命名规避

清单里的"依赖包"是分发单元，语法里的 `包 演示.应用;` 是命名空间，第 22 课「清单 = ArrayList」是集合类——三者同名不同义，ADR-019 明确定义，文档避免混用。
