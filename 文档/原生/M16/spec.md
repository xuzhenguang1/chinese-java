# M16：语义兼容实证（浮点边界 + 无序集合口径冻结）

> 状态：方案待评审。来源为《后续路线计划书-M15至M18》第 4 节，已按 2026-11-22 逐行实测核查校准（计划书里两处行号/用途有误，本文以实测为准）。
> 前置：M0–M15 全部完成并推送（末次提交 `a53e2a8`），全量校验退出码 0，ADR 19 份。
> 本文只做方案与任务边界，任务分解见 `tasks.md`，验收勾销见 `checklist.md`。

## 1. 目标

给浮点打印建立**35 课之外的边界对拍集**，实证原生 `格式化浮点()` 与 JVM `数值.转文本`（`String.valueOf` → `Double.toString`）在边界值上是否逐字节一致；把实证结论与既有的正确行为（无序集合插入序）**冻结进 ADR-007**，并把差异白名单治理流程化，为 M17 的 CI 接入做准备。

### 非目标

- 不做 Ryu 全量移植（现实现已是"可回读最短表示"，先实证再决定是否值得改）。
- 不改无序集合遍历顺序（现为插入序，是正确行为）——只写文档结论，不改 `集合.c`。
- 不新增 ADR 编号，**只修订 ADR-007**（ADR 总数保持 19）。
- 不改特殊值口径（NaN/±Inf/±0.0）、不改 `%f` 的 `%.6f` 独立语义（对齐 Java `Formatter`）。
- 不改 35 课源文件、AST/MIR/语义快照、自举不动点文本。
- 不改 Windows PE / Linux ELF 的 ABI 与运行时接口。

## 3. 核心设计

### 3.1 浮点边界用例集

统一放 `原生/测试/浮点边界/`，每个 `.java` 文件打印一批同类别的值，文件名以 `浮` 开头（便于脚本收集，避免与教程 `^第\d{2}课` 过滤冲突）。覆盖类别：

| 类别 | 代表值 | 关注的规范化分支 |
| --- | --- | --- |
| 特殊值 | `NaN`、`Infinity`、`-Infinity`、`0.0`、`-0.0` | `cjkrt.c:400-411` |
| 十进制区间 | `1.0`、`123.456`、`0.001`、`9999999.0`、`1e-3`、`1e6` | `:452-478` 指数 -3..6 |
| 科学计数法 | `1e-4`、`1e7`、`1.5e10`、`-2.5e-20`、`1e100`、`1e-100` | `:479-489` 大写 E、无 + |
| 有效数字位数 | `1.0/3.0`、`2^53`(9007199254740992.0)、`9007199254740993.0`、15/16/17 位小数 | `:415-426` 回读位数（**重点抓 16 位不足**） |
| 次正规数 | `Double.MIN_VALUE`(4.9e-324)、`Double.MIN_NORMAL` | `:417-426` 回读循环 |
| 舍入临界 | `0.1+0.2`、`2.2250738585072014e-308`、`1.7976931348623157e308`（max） | 最短回读 + 规范化 |
| 单精度 | 上述代表值的 `浮点`/`f` 版本 | `单精度=1` 分支（8 位上限） |

用例只调用 `打印行(数值.转文本(值))` 与 `打印行(值)` 两种形式，确保同时覆盖 `数值.转文本` 的显式路径与 `输出`/字符串拼接的隐式路径。期望值不硬编码——由 JVM 参考实现现场生成，脚本逐字节比对（见 3.2）。

### 3.2 新增 `原生/测试/对拍浮点.ps1`

- **复用骨架**：`对拍原生.ps1:27-49`（路径收集）、`:58-76`（白名单载入/归一化）、`:117-137`（逐字节比较）、退出码 0/1/2。
- **参数**：`-后端 c|llvm`（默认 c）、`-全部`（c 与 llvm 各跑一遍）、`-根目录`、`-路径 <文件...>`（默认收集 `原生/测试/浮点边界/浮*.java`）。
- **流程**：每个用例 → `cjc 编译` 出 JVM class → `java` 跑出 jvm.out；`cjc 原生 [llvm] 编译` 出 exe → 跑出 exe.out；逐字节比较（先原文，再白名单归一化）。
- **结果分类**：每个用例输出 `一致` / `白名单` / `差异` 三态；`差异` 打印两边 stdout 前 12 行供分类。汇总 `通过 N / 共 M`，差异用例列出清单，退出码 1。
- **不做硬编码期望值**：JVM 侧就是期望，避免把某台 JVM 的输出固化成黄金文件。

### 3.3 差异处置分层（T2 的核心纪律）

跑全量边界用例后，**先分类、后动手**：

1. **一致** —— 记录进对拍报告，不动代码。
2. **可小修** —— 差异能在 `格式化浮点()` 的 `:417-426` 或 `:447-490` 内小改修好（如 16 位升 17 位），且不碰特殊值/`%.6f`/指数区间口径，才允许改。每改一处立即跑 `对拍原生.ps1`（35 课）+ `对拍浮点.ps1`。
3. **需登记限制** —— 涉及 Ryu 全量移植、或与既有冻结口径冲突的差异，登记进 ADR-007 新建的「已知限制」小节，**不进白名单**（白名单只放真正不可比项，如随机整数）。

> **硬门槛**：分类未清前不改 `格式化浮点()`；改 ADR 先于改白名单（ADR-007:55 的自身约束）。

### 3.4 无序集合口径冻结（不改代码）

在 ADR-007「无序集合遍历」条目（`:23`）补实测结论：原生实现为**插入序平行数组**（`集合.c:31-36,339-345,470-516`，找键用 `cjk_value_equal` 而非哈希），对拍统一用 `链式键值表`，`HashMap` 遍历顺序不纳入逐字节断言。**不新增白名单条目**。同时把 `:26-30` 的旧条目 1（集合顺序"允许不同"）改写为"已按插入序收敛，非豁免"，消除与白名单现状的矛盾。

### 3.5 白名单治理静态检查

在 `校验.ps1:1482` 新增检查：读 `原生/测试/差异白名单.txt`，逐条（去注释/空行）校验——每条正则必须能在 ADR-007 正文里找到可追溯的条款标记。实现方式采用**轻量锚点约定**：白名单每行形如 `^正则$ ; ADR-007:<锚点>`，或用并行注释行 `# 依据：ADR-007 <锚点>`；具体格式在 T3.2 与现有唯一一条（随机整数）对齐后冻结，避免改动现有对拍脚本的归一化逻辑。目标：任何新增白名单条目若无法指向 ADR 条款即校验失败，为 M17 的 CI 接入铺路。

## 4. 验收口径

1. 边界用例 N/N 逐字节一致，或全部差异均有 ADR-007「已知限制」条款登记（可追溯）。
2. 35 课 C/LLVM × PE/ELF 对拍零回退；`数值.转文本` 与 `数据.转JSON` 冒烟不回退。
3. 白名单治理静态检查通过：现有 1 条随机整数豁免可追溯到 ADR-007；无依据的新条目被拦截。
4. `.\工具\发布\校验.ps1 -含原生` 新增 8.15 后退出码 0；ADR 总数仍为 19（仅修订 007）。
