# 第17批优化规格：枚举语义更清楚，清单更好查

## 1. 目标

继续面向学习者的优化：**减少歧义、补上常用操作、修正示范写法**。不改编译器内部结构，不新增英文关键字映射。

## 2. 发现的问题

| 编号 | 位置 | 问题 |
| --- | --- | --- |
| P1 | 第 18、30 课 | 枚举取全部常量写成 `星期.值集合()`，与映射的 `值集合` 重名，初学者容易误以为枚举是映射 |
| P2 | 第 22 课 | 清单缺少「查下标」的中文写法，只能写英文 `indexOf` 或绕开 |
| P3 | 第 22 课 `数值.移除(整数包装.值(2))` | 写法突兀且没有解释；`移除(2)` 会按位置删除，是新手最常见的误解之一 |
| P4 | 尝试 `链式键值表.从(...)` | 测试发现不可行：若翻译成 `new LinkedHashMap<>(Map.of(...))`，`Map.of` 不保证顺序，第 23 课「按插入顺序」的输出从 `{苹果=6, 香蕉=5}` 变成 `{香蕉=5, 苹果=6}`。已整体回退 |

## 3. 变更明细

### 3.1 `工具\cjc\方法糖.txt`（唯一数据源）

`[成员]` 新增 2 条，成员糖 50 → 52：

- `取出=get` 之后：`找下标=indexOf`
- `值集合=values` 之后：`全部值=values`

约定：**枚举用 `全部值`，映射用 `值集合`**，两者都翻译为 `values()`。

### 3.2 `教程\第18课枚举.java`

```java
对于 (星期 天 : 星期.值集合()) {
```

改为：

```java
对于 (星期 天 : 星期.全部值()) {
```

输出不变（已验证改前/改后 SHA256 相同）。

### 3.3 `教程\第30课综合项目.java`

两处 `科目.值集合()` 改为 `科目.全部值()`（第 35 行平均分、第 78 行单科最高循环）。输出不变。

### 3.4 `教程\第22课清单.java`

- 在第 9 行的按值删除后补注释：`// 按值删除 2；若写 移除(2) 会按位置删除`
- 在「修改并删除后」之后新增一行：

```java
打印行("9 的位置：{数值.找下标(9)}");
```

预期新增输出一行：`9 的位置：1`。

### 3.6 已回退的实验（负面记录）

为「一行建可变映射」尝试过 `链式键值表.从(...)` → `new LinkedHashMap<>(Map.of(...))`，并改动了 `Cjc.java`、第 23/32 课与 `示例\标准库演示.java`。实测第 23 课顺序变化后：

- `Cjc.java` 的构造糖代码全部撤销，净改动为 0；
- 第 23 课、第 32 课、`示例\标准库演示.java` 恢复原写法；
- 结论：除非能保证插入顺序，否则不要再用 `Map.of` 拼可变 `LinkedHashMap`。
