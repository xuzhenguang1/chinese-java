## 1. 护栏（每一步都执行）

1. 基线：改动前各跑一次转译并留哈希
   ```powershell
   .\cjc.ps1 转译 教程 -d 构建\第10批\基线\教程
   .\cjc.ps1 转译 示例 -d 构建\第10批\基线\示例
   Get-ChildItem 构建\第10批\基线 -Recurse -File |
       ForEach-Object { "$($_.FullName.Replace('E:\xiadujava\构建\第10批\基线\','')) $((Get-FileHash $_.FullName).Hash)" } |
       Set-Content 构建\第10批\基线.sha256
   ```
2. 每一步后快速检查
   ```powershell
   .\cjc.ps1 检查 教程 示例 --允许推断
   ```
3. 每完成 1 个步骤就重跑转译并比对哈希（不一致数必须为 0）：
   ```powershell
   .\cjc.ps1 转译 教程 -d 构建\第10批\当前\教程
   .\cjc.ps1 转译 示例 -d 构建\第10批\当前\示例
   # 相对路径 + 哈希与 基线.sha256 做 Compare-Object，要求 0 行差异
   ```
4. 每 2 个步骤跑一次 `.\工具\发布\校验.ps1`；收尾跑 `-含原生`，退出码必须为 0。
5. 每 2 个步骤提交一次，提交信息标明步骤号；出现哈希差异立即回滚该步，不叠加修改。

## 2. 执行步骤

### 10.1 统一致命错误出口（预计 -12 行）

- 位置：`Cjc.java` 中 12 处相邻写法
  ```java
  System.err.println("错误：……");
  System.exit(2);
  ```
- 做法：新增
  ```java
  private static void fail(String line) {
      System.err.println(line);
      System.exit(2);
  }
  ```
  所有 12 处改为 `fail("错误：……")`；`failTable` 内部改调 `fail`。
- 完成标准：`System.err.println("错误…")` + `System.exit(2)` 相邻模式降为 0；`System.exit(2)` 只剩 `fail` 与两处 `usage` 调用点。
- 验证：三条反例的 stderr 文案与退出码不变
  ```powershell
  .\cjc.ps1 检查 教程 --表 构建\不存在.txt          # 期望「错误：找不到关键字表 …」，EXIT=2
  .\cjc.ps1 转译 教程 -d 构建\第10批\临时 --表 构建\缺糖\关键字表.txt  # 期望「方法糖表缺失：…」，EXIT=2
  .\cjc.ps1 检查 教程 --表 构建\坏表\关键字表.txt   # 期望「关键字表错误：第N行…」，EXIT=2
  ```

### 10.2 拆分 `main`（127 → ≤ 35 行）

按命令边界拆成 4 个方法，`main` 只做参数校验与分派：

| 新方法 | 职责 | 从 main 移出的行 |
| --- | --- | --- |
| `validateOptions(Options)` | `-jar`/`-主类` 组合校验、未知命令与空输入 | 190–210 |
| `LoadedSources loadSources(Options)` | `collect` + `load` + 收集 `identifierNames` | 231–242 |
| `CheckCounts runChecks(files, names)` | 4 项检查 + 错误汇总（返回计数，不退出） | 244–254 |
| `runCheckCommand(opt, files, counts)` | `--含编译` / 纯检查的通过输出 | 255–283 |
| `runTranslateOrCompile(opt, files)` | `-d` 校验 + `转译` / `编译` + `打包` | 288–313 |

- 新增两个小的值对象：`LoadedSources`（`files` + `identifierNames`）、`CheckCounts`（4 个计数）。
- 完成标准：`main` ≤ 35 行；退出码与输出顺序保持原样。
- 验证：6 条命令各跑一次（检查 / 编译 / 转译 / 反译 / 运行 / 新建），并跑 10.1 的 3 条反例。

### 10.3 拆分 `planVoidAndPrint`（134 → 60 行以内）

| 新方法 | 职责 | 预计行数 |
| --- | --- | --- |
| `TypeScope planTypeScopes(SourceFile, List<Token>)` | 计算每个下标的类型上下文与「是否在类型体内」 | 48 |
| `boolean[] planVoid(SourceFile, List<Token>, TypeScope)` | 省略返回类型时补 `void` | 35 |
| `void planPrint(SourceFile)` | 语句开头的 `打印行` / `打印` 补 `System.out.` | 35 |

- `TypeScope` 为内部类，持有 `boolean[] inTypeBody`、`String[] typeName`，替代当前两套并行布尔数组。
- 完成标准：原方法只剩「算作用域 → 算 void → 算打印」三行；三段逻辑可独立阅读。
- 验证：教程第 01、08、13、14 课与 `示例\方法糖演示.java` 的转译哈希不变（这几处覆盖省略返回类型与打印糖）。

### 10.4 拆分 `renderTranslated`（186 → ≤ 100 行）

按「整 token 改写」把长分支移出主循环：

| 新方法 | 覆盖的现有分支 |
| --- | --- |
| `int renderRepeat(...)` | `重复 N 次` 展开 |
| `int renderArrayListFrom(...)` | `数组清单.从(...)` → `new ArrayList<>(List.of(...))` |
| `void renderKeyword(...)` | 关键字 → 英文（含 `否则若`、`入口`、`令/常量`） |
| `void renderLiteral(...)` | 字符串插值、全角标点折叠 |
| `void appendPendingClosers(...)` | 预插右括号的补写 |

- 保留现有的 `emit` / `emitToken` / `recordReplacements` 不动，避免位置映射再次出错。
- 完成标准：主循环 ≤ 100 行；`pending` 的登记顺序与偏移完全不变。
- 验证：转译哈希 0 差异；额外用 `示例\标准库演示.java` 与第 31/32 课覆盖 `重复`、`数组清单.从`、插值三条路径。

### 10.5 统一 token 文本访问（-8 处重复表达式）

- 现状：55 处 `prevText(...)` 调用，其中 8 处手写
  ```java
  t.text != null ? t.text : sf.original.substring(t.start, t.end)
  ```
- 做法：
  1. `prevText` 更名为 `textAt`（它取的是「指定下标 token 的文本」，不是「前一个」）；
  2. 新增重载 `textAt(SourceFile, List<Token>, int)`，内部做越界保护并复用上述回退；
  3. 把 8 处手写表达式替换为重载调用。
- 完成标准：`text != null ?` 手写回退表达式为 0；`prevText` 标识符为 0。
- 验证：转译哈希 0 差异；`planCalls` / `planGenerics` / `planPrintArgs` 三条糖路径（成员糖 / 泛型包装 / 打印多实参）均在教程中有覆盖。

### 10.6 词表加载器按分区拆（87/86 → 各约 45 行）

`loadMethodSugar`：

- 完成标准：两个加载器 ≤ 50 行；分区缺失、重复、未知分区的报错文案与顺序不变。
- 验证：

## 3. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `renderTranslated` 拆分改变 `pending` 登记顺序，导致诊断行列错位 | 每步转译哈希比对；额外跑 `--含编译` 检查 |
| `main` 拆分改变输出顺序或退出码 | 6 条命令 + 3 条反例逐条对比 |
| PowerShell 函数参数/作用域改动破坏校验 | 只做等价替换；先在临时副本上跑一遍再替换 |
| 词表加载器拆分区后报错顺序变化 | 保留原 `problems` 追加顺序；用坏表现场比对输出 |

- 不动 `标准库`（已只剩 10 个薄类）、`extension.js`（381 行，结构正常）。
- 不生成文档词表（`语言规范.md` / `教程.md` 的表格仍手工维护）。
