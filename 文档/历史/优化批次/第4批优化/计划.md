## 二、任务明细

### 4.1 泛型实参自动用包装类型

- 现状：`清单<整数包装> 数值 = 新建 数组清单<>();`，教程中出现 17 处；`整数` 是 `int` 的别名，写进泛型会被转成 `List<int>` 编译失败。
- 方案：转译时对**基本类型别名 token** 做局部上下文判断——若前一个非空白 token 是 `<` 或 `,`，且后一个非空白 token 是 `>` 或 `,`，则输出包装类型：
  - `整数`→`Integer`、`长整数`→`Long`、`短整数`→`Short`、`字节`→`Byte`、`浮点`→`Float`、`双浮点`→`Double`、`布尔`→`Boolean`、`字符`→`Character`
  - 不进入泛型时行为不变；`整数包装` 等别名保留兼容。
- 涉及文件：`工具\cjc\Cjc.java`（`translate`，约 1786–2046 行）；`语言规范.md` §3.1；`速查表.md`。
- 验收：
  1. 新增示例 `示例\泛型基本类型.java`，含 `清单<整数>`、`键值表<字符串, 双浮点>`、嵌套 `清单<清单<整数>>`，`.\工具\对话\运行.ps1 示例\泛型基本类型.java` 退出码 0。
  2. `.\cjc.ps1 检查 教程 示例 标准库\src` 零错误、零提示。
  3. 原有 `整数包装` 写法仍通过。
- 风险：只影响泛型实参位置；`整数` 是保留词，不会作为普通操作数出现，误判面很小。

### 4.2 `cjc 检查 --含编译`

- 现状：`检查` 只做 CJK001/002 与 CJK101–105（`Cjc.java` 约 328–344 行），类型错误要等 `运行` 才暴露。
- 方案：新增参数 `--含编译`；预处理检查通过后，复用 `运行` 的 classpath 解析（含 `标准库` 产物）调用 `compile(...)` 到临时目录，失败时中文诊断并退出码 1。默认 `检查` 保持快速、行为不变。
- 涉及文件：`工具\cjc\Cjc.java`（参数解析 + `检查` 分支）、`cjc.ps1` 用法说明、`语言规范.md` §8、`AGENTS.md`。
- 验收：
  1. `.\cjc.ps1 检查 --含编译 教程` 通过。
  2. 构造反例 `整数 甲 = "文本";`，命令退出码 1，输出含中文 javac 诊断与文件名行号。
  3. 不带参数时 `.\cjc.ps1 检查 示例` 输出与现在一致。
- 风险：编译耗时增加，只在新参数下发生。

### 4.3 新增 `记录`（record）关键字

- 现状：关键字表无 `record`（`工具\cjc\关键字表.txt`，第 52 行只有 `instanceof=[是]`）。JDK 25 已支持 record。
- 方案：
  1. 词表二选一：
     - 走词典（推荐，保持单一来源）：在 `工具\cjc\近义词典.txt` 新增组（如 `记录=[记录]`），`关键字表.txt` 写 `record=[记录]`；
     - 走兼容单别名：`关键字表.txt` 直接写 `记录=record`（与 `类=class` 同一写法）；
  2. 跑 `工具\cjc\同步词表.ps1` 更新 VSCode 数据与高亮；
  3. 词表总数变化后，更新 `语言规范.md`、`速查表.md`、`AGENTS.md` 中的「235 词 / 51 组」等计数；
  4. 语法示例：`记录 人(字符串 姓名, 整数 年龄) { }` → `record 人(String 姓名, int 年龄) { }`。
- 可选扩展（不在本项必做）：`密封`→`sealed`、`许可`→`permits`、`非密封`→`non-sealed`。
- 涉及文件：`工具\cjc\近义词典.txt`、`工具\cjc\关键字表.txt`、`工具\cjc\同步词表.ps1` 产物、教程新增第 33 课或并入第 30 课。
- 验收：
  1. `记录` 示例 `.\工具\对话\运行.ps1 教程\第33课记录.java` 输出字段值（默认 `toString`）。
  2. `.\cjc.ps1 检查 教程 示例 标准库\src` 通过，计数与实际一致。
  3. `记录` 不能再用作标识符——仓库全量搜索确认无冲突（教程目前 0 处）。
- 风险：新增保留词；若用户代码里有名为 `记录` 的变量会编译失败（本仓库无此用法）。

### 4.4 文档补充「`是` 已支持模式匹配」

- 现状：`是` 已映射 `instanceof`（`关键字表.txt` 第 52 行 `instanceof=[是]`），`若 (值 是 字符串 文本)` 可直接转成 `if (值 instanceof String 文本)`，JDK 25 可用；规范未记载。
- 方案：只改文档，零代码：
  - `语言规范.md` 新增 §4.19「模式匹配 instanceof」；
  - `速查表.md` 增加一行示例；
  - 可选在 `教程\第19课切换.java` 或第 20 课加一个两行示例。
- 验收：示例 `.\工具\对话\运行.ps1` 通过；文档无 `TODO`。

### 4.5 `数组清单.从(...)` 一行建可变清单

- 现状：可变清单要 4 行（`新建 数组清单<>()` + 多次 `加入`）；现有 `清单.从(...)` 返回不可变 `List.of`。
- 方案：识别 `数组清单 . 从 (`，输出 `new ArrayList<>(List.of(`，并在匹配的右括号后补 `))`（需要在 `translate` 里做括号配对，不能只加 `STATIC_CALLS` 条目）。
- 涉及文件：`工具\cjc\Cjc.java`（`translate` + `pending` 列号映射）、`语言规范.md` §4.16、`速查表.md`。
- 验收：
  1. `清单<字符串> 名单 = 数组清单.从("甲", "乙"); 名单.加入("丙");` 运行输出 3 个元素。
  2. 空参数 `数组清单.从()` 得到空清单。
  3. 错误列号仍指向原文（用 `pending` 映射验证一条错误）。
- 风险：括号配对实现要覆盖嵌套调用，如 `数组清单.从(甲.转文本(), 乙)`。

### 4.6 CJK002 对 `。`/`、` 自动折叠

- 现状：全角句号、顿号属于「无法映射」，CJK002 直接阻断。
- 方案：仅对 `。`→`.`、`、`→`,` 自动纠正并输出提示（新提示码 CJK106「已自动纠正标点」，退出码 0）；字符串字面量、字符字面量、注释内不处理；其余全角标点仍按 CJK002 阻断。提供 `--严格标点` 恢复旧行为。
- 涉及文件：`工具\cjc\Cjc.java`（CJK002 检查与 `translate` 输出映射）、`语言规范.md` §7、`速查表.md`、`工具\发布\校验.ps1`（新增反例/正例）。
- 验收：
  1. `打印行("你好")。` 与 `清单.从("甲"、 "乙")` 均能运行。
  2. 字符串内 `"他说。好"` 保持原样。
  3. `“引号”` 仍报 CJK002。
- 风险：需在 token 层判断，不能做全文替换；注释内替换虽无害但会改原文，暂不处理更稳。

### 4.7 合并两套集合词汇（需确认）

- 现状：`列表/映射` 的 `加/取/个数/为空/排序` 与 cjc 糖的 `加入/取出/元素数/是空/整理` 是两套词；为兼容标准库，`Cjc.java` 维护 `STDLIB_CLASSES` 例外名单，文档写着「两套不能混用」。
- 方案 A（推荐）：删除 `标准库\src\...\列表.java`、`映射.java`，集合统一用 JDK 别名 + 成员糖；`标准库` 保留 `文本/数学/数值/时间/文件/集合工具/并发/网络/日志/数据/输出`（11 类）。
  - 需改：`示例\标准库演示.java`（12 处导入/调用）、`工具\对话\模板\`（文件处理、接口数据、并发任务）、`标准库测试`、`STDLIB_CLASSES`、`语言规范.md`、`速查表.md`、`AGENTS.md`、`README.md`。
- 方案 B：保留两个类，但把方法改成规范名（`加入/取出/元素数/是空/整理/放入`），旧名保留 `@Deprecated` 别名。
- 验收（按选定方案）：
  1. `mvn -q -f 标准库\pom.xml test` 通过；
  2. `.\工具\对话\运行.ps1 示例\标准库演示.java` 通过；
  3. 文档中不再出现「两套不能混用」。
- 风险：破坏标准库 API；需在 CHANGELOG 标注不兼容变更。执行前先确认选 A 还是 B。

### 4.8 `打印行` 多参数自动拼接

- 现状：`打印行("姓名：", 名字)` 无法编译，只能手写 `+` 或字符串插值。
- 方案：语句开头的 `打印行(...)`/`打印(...)` 若实参多于 1 个，在顶层逗号处转成 `+` 拼接；含运算符的实参加括号，保证优先级；单参数保持原样。
- 涉及文件：`工具\cjc\Cjc.java`（`translate` 的打印糖分支）、`语言规范.md` §4.6、`速查表.md`。
- 验收：
  1. `打印行("姓名：", 名字, "，年龄：", 年龄);` 输出一行完整文本。
  2. `打印行(甲 + 乙, 丙 * 2);` 语义与手写 `+` 一致。
  3. 单参数、`.打印行` 前缀、自定义同名方法不受影响。
- 风险：需正确识别顶层逗号（嵌套调用、字符串内逗号）。

### 4.9 VSCode 实时诊断

- 现状：只在保存时跑 `cjc 检查`（`extension.js` 的 `onDidSaveTextDocument`）。
- 方案：增加 `onDidChangeTextDocument` 500ms 防抖检查；同一文档复用/取消上一次进程；保存时仍立即检查。若 4.2 完成，可选开启 `--含编译` 显示类型错误（默认关闭，避免频繁编译）。
- 涉及文件：`工具\vscode-中文java\extension.js`、`package.json`（配置项 `cjc.checkOnType`）、`README.md`。
- 验收：
  1. 输入 `私有字符串标题` 后约 1 秒内出现 CJK001 波浪线；
  2. 快速连续输入不产生进程堆积；
  3. `node --check extension.js` 通过，`npx --no-install @vscode/vsce package` 生成新 vsix。
- 风险：大文件频繁检查耗 CPU；用防抖 + 单进程取消控制。
