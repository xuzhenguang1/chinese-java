# 第16批优化规格：让教程更短、更中文

## 1. 目标

延续第 15 批的方向，只做面向学习者的一侧：**代码更短、写法更中文、教程不自相矛盾**。不改编译器内部结构，不新增英文关键字映射，不做与学习无关的重构。

用户原话：「我说的优化是值可以让人易学，代码简单，中文化编程，编写简单的代码」。

## 2. 已确认的问题（来自本批盘查）

| 编号 | 位置 | 问题 |
| --- | --- | --- |
| P1 | `教程\第31课重复循环.java` 第 2 行注释 | 写成 `for (var 序号 = 0; 序号 < 3; 序号++)`，与实现不符。`Cjc.java` 第 2407/2494 行与 `速查表.md` 第 112 行都是 1 起算：`for (int 序号 = 1; 序号 <= 3; 序号++)` |
| P2 | `教程\第25课泛型.java` 第 28 行 | 仍用旧写法 `盒子<整数包装>`；第 15 批已支持泛型实参直接写基本类型，应改为 `盒子<整数>` |
| P3 | `教程\第30课综合项目.java` 第 48 行 + 第 65–67 行 | 先 `新建 数组清单<>()` 再连续 3 次 `加入`；可一行 `数组清单.从(甲, 乙, 丙)` |

## 3. 变更明细（逐文件、逐位置）

- `转大写=toUpperCase` 之后新增 `转小写=toLowerCase`

## 4. 明确不做

- 不新增 `整数.解析` 之类可能影响关键字词法路径的静态糖（风险高于收益，留待后续单独评估）。
- 不新增 `链式键值表.从` 构造糖（需要改 `Cjc.java`，超出「小步」范围）。
- 不改标准库、不改诊断码、不改关键字表与近义词典。
- 不自动推送 GitHub。
