# M5 标准库全量 + 集合与泛型 实施计划

## Context（为什么做）

M4 已让原生后端（MIR 解释器 + C 后端 + cjkrt）在教程 01–21 上与 JVM 逐字节一致，全量校验退出码 0。
现在 `.\cjc.ps1 原生 检查 教程` 虽然 35/35 解析成功，但原生语义分析对 `清单` 等类型直接报
「M4 暂不支持：类型「清单」」。M5 要补齐教程 22–35 所需的类型系统、运行时集合、泛型擦除、
记录/密封/内部类/λ/流，并按用户决策实现 10 个标准库类的全部公开 API。

验收以真实命令输出为准，不接受「看起来对」。

## 目标与验收

1. 教程 22–30：原生 exe 的 stdout、退出码与 JVM 逐字节一致。
2. 教程 31–35：同样逐字节一致（31 重复、32 流/λ、33 记录、34 密封、35 产出/切换表达式）。
3. 10 个标准库类（`输出`/`文本`/`数值`/`时间`/`文件`/`集合工具`/`并发`/`网络`/`日志`/`数据`）
   的公开方法全部有 C 运行时实现；确实无法对齐 JDK 的方法返回明确中文诊断（不允许链接错误或空值）。
4. `.\cjc.ps1 原生 对拍 教程` 与 `.\cjc.ps1 原生 对拍原生 教程` 均 35/35。
5. `.\工具\发布\校验.ps1 -含原生` 退出码 0，新增 M5 断言；01–21 行为与 M4 快照零差异。
6. 差异白名单只登记两项：第 29 课随机整数行、平台/时间相关行（见风险）。

## 关键设计

### 1. 类型系统

- `类型` 增加泛型实参：`类类型(名, 实参列表)`；`同型` 对泛型类先比原始类名，再比实参（用于集合元素推断）。
- 内置类型族（隐式类，不生成 MIR 类定义）：
  - `清单<T>` ← `数组清单<T>`；`键值表<K,V>` ← `链式键值表<K,V>`；`集<T>` ← `散列集<T>` / `哈希表`
  - `文本构建器`、`文件路径`、`可选值<T>`、`流<T>`、`比较器<T>`
  - 包装类：`整数包装`/`长整数包装`/`双浮点包装`/`布尔包装`/`字符包装`（仅用于装箱/拆箱与 `整数.值`）
  - 标准库：`输出`/`文本`/`数值`/`时间`/`文件`/`集合工具`/`并发`/`网络`/`日志`/`数据`
  - 日期：`本地日期`、`本地日期时间`、`日志记录器`、`响应`、`线程池`、`未来`
  - 异常补充：`输入输出异常`（继承 `异常`）
- 泛型擦除：泛型类/方法的类型参数一律按 `对象` 处理；`泛型方法` 的类型参数在其方法体内也按 `对象`。
- 泛型集合保留静态元素类型用于：`取出`/`值集合`/`流` 的返回类型、λ 形参推断、增强 for 变量检查。

### 2. 值模型（C 运行时）

- 新增 `cjk_value { int32_t kind; union { int64_t i; double d; void* p; } }`，kind：
  `空/整数/长整数/双浮点/布尔/字符/引用`。
- 集合元素、Map 键值、Stream 元素、Optional 值、Future 结果统一用 `cjk_value` 存取；
  静态类型到 `cjk_value` 的转换由 C 生成器按类型插入（`cjk_v_i32` / `cjk_v_ref` …）。
- 集合对象首字段为 `cjk_class*`，因此可直接走对象模型与 GC：
  - `cjk_list`：动态数组 `len/cap/cjk_value*`；`cjk_map`：插入有序哈希表（键值对数组 + 索引）；`cjk_set`：去重列表。
  - `cjk_builder`、`cjk_optional`、`cjk_stream`、`cjk_path`、`cjk_date`、`cjk_logger`、`cjk_pool`、`cjk_future`。
- 打印/`转文本` 统一走 `cjk_value_to_string(v, to_string_slot)`：基本类型直接格式化，
  引用类型调用对象描述的 `to_string` 函数指针（类描述符新增该字段；未重写时输出 Java 默认 `类名@哈希`）。
- 列表 `toString` 对齐 `ArrayList`：`[a, b]`；Map 对齐 `LinkedHashMap`：`{k=v, k2=v2}`；Set 对齐 `LinkedHashSet`。

### 3. λ 与方法引用

- λ 降级为**合成类**：类名 `__λ<N>`，捕获变量成为字段，构造器按捕获值赋值，
  实例方法 `调用(形参...)` 承载原方法体。
- `新建 合成类(捕获...)` 复用现有 `新建对象`，解释器/C 生成器无需认识 λ。
- 方法引用 `学生::总分` 合成 `__方法引用<N>`：方法 `调用(学生)` 体内 `返回 参数.总分()`。
- `比较器.按整数(λ)` → 合成比较器类（字段 `键`，方法 `比较(对象,对象)` = 整数差）；
  `.反序()` → 合成包装类（字段 `内层`，方法 `比较` 交换实参）。
- `整理(集合, 比较器)`、`流.过滤/变换/遍历`、`可选值.存在时` 由运行时按「对象 + 虚槽号」回调。
  槽号在 C 生成器全局编号，调用点把槽号传给运行时。

### 4. 产出（yield）与切换表达式

- 新增 MIR `顺序表达式(类型, List<语句> 前奏, 表达式 结果)`：
  C 生成逗号表达式 `(语句..., 结果)`，解释器顺序执行。
- `切换表达式` 的块分支若以 `产出 值` 结尾，降级为「前奏语句 + 顺序表达式」；
  只有表达式语句/局部变量/产出时支持，其他块形式给明确诊断。
- `切换语句` 保持 M4 行为。

### 5. 内部类与记录

- 嵌套类统一扁平命名为 `外部$内部`，`类符号` 记录所属外部类与外层类表。
- 成员内部类自动加隐藏字段 `__外部`（类型为外部类），构造时由 `新建 内部(...)`
  自动传入当前 `这`；内部直接访问外部字段时生成 `这.__外部.字段`。
- 静态嵌套类按普通类处理，`新建 内部` 与 `工具.常量.前缀` 通过当前类的外层类表解析。
- `记录 学生(字符串 姓名, 整数 年龄)` 在语义阶段直接生成：
  字段（final 忽略）、规范构造器、访问器 `姓名()`/`年龄()`、`转文本`/`等于`/`哈希码`。
  - `转文本` 对齐 Java：`学生[姓名=小明, 年龄=18]`
  - `哈希码` 对齐 Java record：`31*(31*1 + 姓名.hashCode()) + 年龄`（字符串用 Java `String.hashCode`）
  - `等于`：同类 + 各分量 `Objects.equals`
  - 记录实现接口/带自定义方法（第 34 课 `记录 方(...) 实现 形状`）照常生成。
- `密封`/`许可`/`非密封`：许可列表仅做记录，不做类型检查；`非密封 类` 按普通类处理。

### 6. 命令行参数与文件

- `入口` 方法自动定义 `参数`（`字符串[]`），初值为内建 `程序参数`；
  解释器从 `运行` 的实参传入，C 入口把 `argc/argv` 转 UTF-8 字符串数组。
- `文件路径` 内部保存绝对路径字符串；`文件路径.取(段...)` 按平台拼接并规范化为绝对路径。
- `文件助手` / `文件` 的读、写、建目录、存在、读所有行、列举、大小、删除均走 UTF-8；
  `读所有行` 忽略末尾空行（对齐 `Files.readAllLines`）；失败抛 `输入输出异常`。

## 风险与边界

- **第 29 课随机整数**：JVM 与原生随机序列不可能一致，按路线图第 8 节登记差异白名单，只过滤 `随机整数：` 行。
- **第 33 课哈希码**：必须实现 Java `String.hashCode` 与 record 哈希公式，不能白名单。
- **浮点打印**：沿用 M3 的 Java 兼容最短表示；第 30/34 课的双浮点必须逐字节一致。
- **并发**：Windows 线程实现；GC 扫描需登记工作线程栈（`cjk_gc_register_thread`），否则任务中分配可能被误回收。
- **网络**：WinHTTP 实现 HTTPS GET，仅保证 Windows 一期；失败抛 `输入输出异常`。
- **时间**：`格式化` 支持 `yyyy/MM/dd/yyyy-MM-dd HH:mm:ss` 等常用模式；未识别模式给明确诊断。
- **明确不支持**：带标签的跳出/继续、可变参数（λ 可变参数）、未在 22–35 出现的复杂语法，继续给「M5 暂不支持」中文诊断。
- 不修改 `工具\cjc\Cjc.java` 的 JVM 转译链路；不改 `工具\cjc\关键字表.txt` 的既有映射，新类型在原生语义层识别。
