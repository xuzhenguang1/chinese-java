# M7 工具链与生态 实施计划

## Context（为什么做）

M6 已交付 LLVM 后端，教程 01–35 在 JVM / C / LLVM 三套后端上逐字节一致，
`.\工具\发布\校验.ps1 -含原生` 退出码 0。路线图第 7 节把 M7 定义为「工具链与生态」，
验收口径是两条：

1. `cjc.ps1 新建 项目` 后，一条命令产出 exe；
2. VSCode 诊断来自新前端。

范围已与用户对齐：

- 脚手架：**改造 `新建 项目` 为原生优先**，同时保留 `mvn package` 的 JVM 路径；
- 编辑器：**新前端 JSON 诊断 + 补全扩充**，不做完整 LSP 服务；
- 其余路线图项：**本期只做增量编译**；包管理、交叉编译、自举写入 ADR-010，明确不做。

硬约束：

- C 后端仍是默认后端，M7 不改变任何既有产物与 35 课对拍结果。
- 词表仍只有 `工具\cjc\` 一份；`原生\` 下不得出现词表副本。
- 全部中文交流与中文诊断；不支持的组合必须报明确中文错误，不允许静默降级。
- 临时产物放 `构建\`，结束清理；提交前询问用户，不推送。

## 现状与缺口

| 能力 | 现状 | M7 缺口 |
| --- | --- | --- |
| `新建 项目` | 生成 `pom.xml` + `src\main\中文\演示\应用\主程序.java`，只能 `mvn package` 出 jar | 没有 `构建.ps1`，没有 exe 产物 |
| 原生前端语法 | 支持 `导入`，**不支持 `包`** | 模板带 `包 演示.应用;`，原生编译直接语法失败 |
| VSCode 诊断 | `extension.js` 直接 spawn `Cjc.java 检查`，正则解析文本 | 诊断来源是旧转译链路，不是新前端 |
| VSCode 补全 | 只有 `关键字数据.json`（关键字） | 缺类型别名、方法糖、标准库类名 |
| `原生 编译` | 每次全量编译 6 个运行时 `.c` + 模块 `.c`，无缓存 | 重复构建耗时固定，无「未变更跳过」 |
| 包管理 / 交叉编译 / 自举 | 无 | 本期只写决策，不实现 |

## 目标与验收

1. `.\cjc.ps1 新建 项目 构建\M7脚手架\示例工具` 后，在项目内执行 `.\构建.ps1`
   产出 `target\应用.exe`；运行输出 `你好，示例工具！`，退出码 0。
2. `.\cjc.ps1 原生 诊断 --json <文件>` 输出逐行 JSON，字段为
   `码 / 行 / 列 / 长度 / 消息 / 建议 / 错误`；CJK001、CJK002、CJK106、CJK101–CJK105
   与旧链路命中一致；有诊断时退出码仍为 0（诊断是数据），内部失败才用 2。
3. VSCode 扩展默认调用新前端（配置项可回退旧链路），诊断范围、严重级别、
   Quick Fix 与现状一致；补全增加类型别名、方法糖、10 个标准库类名。
4. 增量编译：同一工程连续构建两次，第二次输出「增量：…跳过」且明显更快；
   `-无缓存` 与缓存构建产物逐字节一致，35 课对拍不受影响。
5. `.\工具\发布\校验.ps1 -含原生` 退出码 0；M1 AST 快照、M5 C 对拍、M6 LLVM 对拍、
   DWARF、基准零变化。

## 关键设计

### 1. `包` 声明最小支持（不扩展 AST）

原生前端只为「能编译工程模板」补一条顶层语法，不改变 AST 与快照：

- `语法分析器.解析()` 在 `导入` 之前识别 `包 <名称> ;`，消费标记并丢弃；
- 不新增 `编译单元` 字段，`语法树打印器`、35 份 AST 快照、语义分析器均不改；
- `前端主程序` 的类名、入口识别沿用「`入口` 方法」规则，与包名无关；
- 出现在非顶层位置的 `包` 仍按现有语法错误处理。

### 2. JSON 诊断协议

`前端主程序` 新增命令：

```
前端主程序 诊断 <根目录> <文件> [--json]
```

- `--json`：每个诊断一行 JSON，stdout 只输出 JSON，不打印文件名/统计等噪声；
  字段固定为 `码`、`行`、`列`、`长度`、`消息`、`建议`、`错误`。
- 无 `--json` 时复用现有 `诊断.打印` 文本格式，便于人工排查。
- `诊断.项` 增加 `长度` 字段，默认 1；词法层对 CJK001/CJK002/CJK106/非法字符
  记录真实宽度，其余保持 1。旧调用点使用重载方法，不改语义。
- 退出码：成功输出诊断（无论是否有错误）= 0；读文件失败/内部异常 = 2。

`原生\驱动.ps1` 新增子命令 `诊断`：

```
.\cjc.ps1 原生 诊断 [--json] <文件或目录...>
```

先做前端缓存编译（复用 `确保前端已编译`），再转发到 `前端主程序 诊断`；
目录按现有规则展开 `.java`。

### 3. VSCode 接入

`工具\vscode-中文java\extension.js`：

- 新配置 `cjc.diagnosticSource`：`"原生"`（默认）/ `"兼容"`；
  找不到 `原生\驱动.ps1` 或新前端启动失败时自动回退旧链路并提示一次。
- 检查进程：若 `构建\原生\前端\classes` 已存在，直接
  `java -cp <classes> 中文.原生.前端.前端主程序 诊断 <root> <file> --json`；
  否则调用 `cjc.ps1 原生 诊断 --json <file>`（会先编译前端）。
- 解析逐行 JSON，`行`/`列`/`长度` 直接映射 `vscode.Range`；
  `错误=false` 映射 Warning，其余 Error；`source='cjc'`、`code=码` 保持不变，
  现有 Quick Fix（CJK001/002/101/103/104/106）逻辑不改。
- 临时文件检查（未保存内容）沿用现有机制。

### 4. 补全数据

`工具\cjc\同步词表.ps1` 在生成 `关键字数据.json` 之外，新增生成
`工具\vscode-中文java\补全数据.json`（保持旧文件格式不变）：

```json
{
  "类型别名": { "字符串": ["String", "…"] },
  "方法糖": { "成员": { "加入": ["add", "…"] }, "声明": {}, "静态": {} },
  "标准库": { "输出": "…", "文本": "…" }
}
```

- 计数必须与关键字表/方法糖表一致（类型别名 34、成员 52、声明 3、静态 56、白名单 10）。
- `extension.js` 读取该文件，按类别给出 `CompletionItemKind`：类型别名 Class、
  成员/静态 Method、标准库 Module；中文后仍自动补空格。
- `校验.ps1` 增加「补全数据与词表计数一致」断言。

### 5. 增量编译

只改 `原生\驱动.ps1`，不改后端与运行时语义：

- 缓存目录：`构建\原生\缓存\`
  - `运行时\<名>-<内容哈希前8>.o`：每个运行时 `.c` 按内容哈希编译一次；
  - `模块\<模块>-<C内容哈希前8>.o`：前端生成的 C 文本哈希决定是否复用；
  - `状态\<模块>.json`：记录 `sourceHash / runtimeHash / exePath / exeTime`。
- `原生 编译` 流程：
  1. `-无缓存` 关闭全部缓存；否则先比对 `状态` 中的 sourceHash、runtimeHash、
     exe 是否存在，全部命中直接输出「增量：源文件与运行时未变，跳过」并退出 0；
  2. 前端生成 C（保持现有位置 `构建\原生\<模块>.c`，便于人工检查）；
  3. 模块 C 哈希命中则跳过 `clang -c`，运行时 `.o` 逐个按内容哈希复用；
  4. 只用缓存的 `.o` 链接出 exe，编译/链接旗标固定为现有
     `-O2 -std=c11 -fwrapv -fno-strict-aliasing -static`，避免 ABI 漂移；
  5. 成功后写回 `状态\<模块>.json`。
- `原生 llvm 编译` 复用同一套运行时 `.o` 缓存；IR 模块 `.o` 用 `.ll` 内容哈希。
- 输出增加一行统计：`增量：运行时命中 X/Y，模块命中/未命中`，供校验断言。
- 任何缓存异常（文件损坏、哈希不符）一律重新编译，不报错退出。

### 6. 工程脚手架（原生优先）

`Cjc.java` 的 `createProject` 增加生成 `构建.ps1`（内容随项目生成）：

```powershell
# 在项目根目录执行：.\构建.ps1
$根 = Split-Path -Parent $PSScriptRoot
$cjc = Join-Path $根 "<相对仓库路径>\cjc.ps1"
& $cjc 原生 编译 "src\main\中文\演示\应用\主程序.java" -o "target\应用.exe"
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
Write-Host "已生成：target\应用.exe"
```

- 相对仓库路径沿用 `pom.xml` 里已有的 `relative` 计算；跨盘符时回落绝对路径。
- 保留 `pom.xml` 与 `包 演示.应用;`，`mvn package` / `java -jar` 路径不变；
  原生路径由第 1 节的 `包` 支持保证可编译。
- 生成后的提示改为两条：`.\构建.ps1` 出 exe；`mvn package` 出 jar。

### 7. 测试与校验

`工具\发布\校验.ps1`：

- 7.6 脚手架：生成后实际执行 `构建.ps1`，断言 `target\应用.exe` 存在、
  运行输出 `你好，示例工具！`、退出码 0（M7 核心验收）。
- 新增 8.5 原生 M7：
  - `原生 诊断 --json` 对含 CJK001 + CJK106 的临时文件输出可解析 JSON，
    字段齐全、码命中、退出码 0；
  - 连续两次 `原生 编译` 同一文件：第二次输出含「增量」，
    且两次 exe 输出一致；
  - `-无缓存` 与缓存构建的 exe 输出一致；
  - `extension.js` 含 `原生 诊断` 且 `node --check` 通过；
  - `补全数据.json` 计数与词表一致。
- M0 的 ADR 数量断言从 9 改为 10（新增 ADR-010）。

## 任务顺序

1. **T1 前端 `包` + JSON 诊断**：语法分析器消费 `包`；`诊断.项` 加长度；
   `前端主程序 诊断 --json`；回归 `原生 检查 教程` 35/35、10 条反例、AST 快照零差异。
2. **T2 驱动诊断 + 增量编译**：`原生 诊断`；运行时/模块 `.o` 缓存、状态文件、跳过逻辑、
   `-无缓存`；实测第二次构建明显变快且产物一致。
3. **T3 脚手架改造**：`新建 项目` 生成 `构建.ps1`；在 `构建\M7脚手架\示例工具`
   实测一条命令出 exe 并运行。
4. **T4 VSCode 扩展**：诊断切新前端、回退开关、补全数据接入；
   `node --check`、`npx --no-install @vscode/vsce package` 重建 vsix。
5. **T5 校验接入**：脚手架 exe、M7 诊断/增量/补全断言、ADR 计数 10。
6. **T6 文档**：ADR-010、M7 spec/tasks/checklist、路线图回填。
7. **T7 全量回归**：`.\工具\发布\校验.ps1 -含原生` 退出码 0；清理 `构建\` 临时文件。
8. **T8 交付**：汇总真实命令输出，询问是否提交（不推送）。

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `包` 改动影响 AST/快照 | M1 回归失败 | 只消费不建节点；跑 35 份 AST 快照零差异 |
| 新前端诊断与旧链路不完全等价 | 编辑器漏报 | 先在 `校验.ps1` 对比 CJK001/002/106/101–105；保留 `兼容` 回退 |
| 每次输入启动 PowerShell 变慢 | 编辑卡顿 | classes 已存在时直接 spawn java；保留 500ms 防抖 |
| 缓存哈希失效/ABI 漂移 | 产物错误或链接失败 | 哈希覆盖源码+运行时+旗标；异常自动重编；`-无缓存` 对照 |
| exe 被杀毒占用 | 启动 Access denied | 沿用现有 5 次×1s 重试 |
| vsix 未重建 | 分发旧扩展 | 改 `extension.js` 后必须 `vsce package`，校验检查时间戳/内容 |
| 包管理/交叉编译范围膨胀 | M7 失控 | 写入 ADR-010 明确不做，只保留清晰中文提示 |

## 明确不做

- 完整 LSP 服务端（languageclient + 独立进程协议）。
- 远程包仓库、依赖解析、版本冲突求解。
- Linux ELF / macOS Mach-O 交叉编译（只写决策，不实现）。
- 自举（原生编译器编译自身）。
- 原生多文件/跨包语义（脚手架保持单文件；目录编译仍逐个文件）。
