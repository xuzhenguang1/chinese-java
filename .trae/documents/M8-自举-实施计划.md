# M8 实施计划：自举一期（词法自举）

- 日期：2026-11-13
- 方向：自举（用户已确认）
- 一期范围：词法自举（用户已确认）
- 验收对拍范围：教程 35 课（用户已确认）

## 1. 目标

用**中文 Java** 重写编译器的词法层（词表读取 + 词法分析 + CJK001/002/106 诊断），
经现有原生后端编译成 **Windows exe**，在**不依赖 JVM** 的前提下，
对 35 课教程产出与 Java 参考实现**逐字节一致**的 Token 流与词法诊断。

一期完成后，编译器链路中的第一层由本语言自身实现并运行，后续 M9 再推进语法、
语义、MIR 与后端自举，最终达成完整自举。

## 2. 现状与探测结论

`原生\` 共 4 个 Java 模块（前端 / 中间表示 / 后端C / 后端LLVM），约 1.4 万行：

| 模块 | 行数 | 自举可行性 |
| --- | --- | --- |
| 词法 + 词表读取（`标记/词表/词法分析器/诊断`） | 约 900 | 高，已探测通过 |
| 语法分析器 | 1041 | 中，需大量补特性，二期 |
| 语义分析器 | 3178 | 低，依赖正则/Character/Files，三期 |
| 解释器 / 后端 | 约 6000 | 低，后期 |

本次用真实程序在原生后端上探测，结论：

已支持（直接可用）：多顶层类与嵌套静态类、`record`、`枚举`、`入口` 糖、
`文件路径.取` / `文件助手.读所有行`、`取字符` / `取子串` / `以开头` / `含有` /
`相等` / `长度`、`文本构建器`、`键值表`、`数组清单` + `加入` / `取出` / `排序`、
`整数.解析`、字符字面量与 `(整数) 字符` 强转、`新建 整数[n]` 与 `.长度`、
`当` / `若` / `跳出`、`最终` 静态常量。

必须补的两个缺陷（探测中真实触发）：

1. **原生 exe 非 ASCII 命令行参数乱码**
   `.\探测.exe 工具\cjc\关键字表.txt` 报「无法读取文件：����\cjc\...」。
   `cjk_set_args` 直接把 ANSI `argv` 当 UTF-8 解码（`原生\运行时\值.c`）。
   自举词法器必须接收中文路径，故必须先修。
2. **`字符串.比较` 实例形式崩溃**
   `甲.比较(乙)` 在 C 后端抛 `IndexOutOfBoundsException`（`C生成器.java:1265`
   假设实参恒为 2 个）；LLVM 后端同样问题（`LLVM生成器.java:2296`）。
   语义分析器把接收者放进内建调用（`语义分析器.java:1810-1820`），两个后端未处理。

## 4. 输出格式（两套实现共用，逐字节可比）

`原生 分词` 与 `分词器.exe` 输出同一格式：

```
文件|<文件名>
标记|<类别>|<行>|<列>|<原文>|<规范>
诊断|<错误|提示>|<码>|<行>|<列>|<长度>|<消息>|<建议>
汇总|<文件数>|<标记数>|<错误数>|<提示数>
```

- 字段内转义：`\\` → `\\\\`，`\n` → `\\n`，`\r` → `\\r`，`\t` → `\\t`，`|` → `\\|`。
- 文件顺序：按路径字典序，与现有前端 `收集文件` 一致。
- 诊断顺序：与 `诊断.列表` 的插入顺序一致（先词法，再 CJK001 粘连）。
- 行尾统一 `\n`，不输出空行。

`分词` 只覆盖**词法层**诊断：CJK001 粘连、CJK002 坏标点、CJK106 标点纠正。
CJK101–105 属于语义提示层（`诊断.新手检查`），不进一期对拍（见第 7 节）。

## 5. 任务分解

### T1 口径与缺陷修复

1. `前端主程序` 新增 `分词 <根目录> <文件或目录...>`：
   复用 `词表.读取`、`词法分析器.分析`、`词法分析器.检查粘连`，按第 4 节格式输出。
2. 修 `原生\运行时\值.c` 的 `cjk_set_args`：
   `_WIN32` 下用 `GetCommandLineW` + `CommandLineToArgvW` 取宽字符参数，
   再 `WideCharToMultiByte(CP_UTF8)` 转 UTF-8；非 Windows 保留现状。
   链接参数补 `-lshell32`（C 后端与 LLVM 后端两处）。
3. 修 C / LLVM 后端 `字符串比较`：接收者非空时按
   `cjk_str_compare(接收, 实参[0])` 生成。
4. 加回归样例：`示例\字符串比较示例.java`（或并入现有示例）覆盖静态与实例两种写法。

验收：
- `.\cjc.ps1 原生 分词 教程` 输出稳定，重复执行一致；
- `.\cjc.ps1 原生 编译 示例\字符串比较示例.java -o 构建\原生\字符串比较示例.exe` 后运行结果正确；
- 中文路径 exe 参数可读：`构建\原生\字符串比较示例.exe` 无乱码；

## 7. 明确不做（一期边界）

| 项 | 原因 |
| --- | --- |
| 语法 / 语义 / MIR / 后端自举 | 依赖大量原生暂不支持的 API，留 M9+ |
| CJK101–105 新手提示 | 属语义提示层，不是词法器职责 |
| Unicode 标识符全量分类 | 用 BMP 常用区间，教程范围等价；边界写入文档，不静默豁免 |
| 多文件工程编译 | 原生前端仍为单文件语义 |
| 性能优化 | 先正确后优化 |
| 词表内容复制 | 继续只读 `工具\cjc` 四份词表，单一数据源 |
