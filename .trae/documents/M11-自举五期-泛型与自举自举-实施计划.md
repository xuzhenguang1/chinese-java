## 2. 目标与验收口径

1. 教程 22–35 中间码：14 份与 `原生 中间` 逐字节一致。
2. MIR 快照：35/35 一致（现有 21 份 + 新增 14 份）。
3. 自举自举第一阶：自举 exe 对 `原生\自举\自举前端.java` 产出的 MIR，与参考实现逐字节一致。
4. 自举自举第二阶（不动点）：用第一阶 MIR 经 C 后端编译出 exe B；B 对自身产出的 MIR
   与 A 一致，B 跑教程 01–35 的分词/语法/语义/中间码输出与 A 一致。
5. `.\cjc.ps1 原生 自举` 新增五期 2/2 通过；`.\工具\发布\校验.ps1 -含原生` 退出码 0。

## 3. 范围

**做**：内置类型/标准库类解析、泛型（含泛型类与方法、类型参数约束）、成员/静态内部类、
λ 与流（捕获分析与 `__λN` 合成类）、记录、密封类、`产出`、切换表达式剩余形态、
标准库内建调用表、自举自举两级验证。

**不做**：多文件共享符号表、解释器扩展、C/LLVM 后端改动、包管理、跨平台、
性能优化、替换生产路径的 Java 参考实现。

## 4. 任务分解

每一步都以「可运行 + 真实命令输出」收尾，不允许只看代码。

### T1 快照基线扩到 35

- 改 `原生\测试\生成MIR快照.ps1`：默认范围扩到 `^第(0[1-9]|[12][0-9]|3[0-5])课`，注释同步。
- 生成 22–35 共 14 份新快照到 `原生\测试\MIR快照\`。
- 验收：`.\原生\测试\生成MIR快照.ps1` 输出 `MIR 快照：35 份`；抽查第32课快照含 `__λ1`。

### T2 内置类型与标准库类解析

- 在 `原生\自举\自举前端.java` 补一张与参考实现等价的内置类表：
  集合别名（`清单`/`数组清单`/`键值表`/`链式键值表`/`集`/`散列集`/`文本构建器`/`可选值`/`收集器`/`流`）
  与标准库 10 类（`输出`/`文本`/`数值`/`时间`/`文件`/`集合工具`/`并发`/`网络`/`日志`/`数据`）。
- 语义层：解析到内置类时给「内置类型」而非「错误类型」；未知标识符仍按现有诊断。
- 降级层：变量类型、字段类型、返回类型保留泛型文本（如 `清单<文本>`）。
- 验收：第22–24课（清单/键值表/文本构建器）中间码逐字节一致。

### T3 泛型

- 镜像参考实现的擦除口径：`清单<文本>` 在 MIR 中保留类型文本，但方法/构造器匹配按擦除名。
- 泛型类、泛型方法、`<元素类型 继承 可比较<元素类型>>` 类型参数约束（第25课）。
- 验收：第25课中间码逐字节一致；`清单<整数>` 与 `清单<文本>` 不误判重复声明。

### T4 内部类与静态嵌套类

- 第26课：成员内部类、静态嵌套类的全名与构造器调用形态，按参考 MIR 镜像。
- 验收：第26课中间码逐字节一致。

### T5 标准库内建调用表

- 覆盖第27–30课用到的 `文件助手` / `文件路径` / `输出` / `数值` / `集合助手` / `可选值` / `枚举` 调用，
  按参考实现生成 `调用 内建 <名>`，不引入新内建名。
- 未登记的方法一律走现有「失败」诊断，禁止静默降级。
- 验收：第27–30课中间码逐字节一致；第28课带参数运行输出与 JVM 一致。

### T6 λ 与流

- 捕获分析：按外层当前可见局部变量（含参数与 `这` 字段？参考实现只捕获局部）生成字段，
  字段顺序与参考 MIR 一致。
- 合成类命名 `__λN`（N 从 1 递增，按出现顺序）；方法名 `调用`；无返回值时返回类型 `无`，
  有返回值时按推断类型（参考实现用 `__值` 占位）。
- 流与收集器：`清单流` / `流过滤` / `流变换` / `流收集清单` / `流收集拼接` / `收集器清单` /
  `收集器拼接` / `字典遍历`。
- 验收：第32课中间码逐字节一致，且 MIR 中 `__λ1/__λ2/__λ3` 的字段顺序与参考一致。

### T7 记录、密封、产出与切换

- 记录（第33课）：按参考 MIR 合成字段、构造器、访问器、`转文本`、`等于`、`哈希码`。
- 密封 / 许可 / 非密封（第34课）：类头 `密封` 标记与 `实现` 列表。
- `产出`（第35课）：切换表达式内的 `产出` 降级形态。
- 验收：第33–35课中间码逐字节一致。

### T8 22–35 全量对拍

- 扩 `原生\测试\对拍中间码.ps1`：教程 01–35、MIR 快照 35/35；输出行数统计更新。

  `自举中间码对拍：通过 2 / 共 2 项`。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| λ 捕获字段顺序与参考不一致 | 以第32课 MIR 为唯一口径，先抄参考的收集顺序 |
| `__λN` 编号在多文件/多次降级时漂移 | 序号按文件内出现顺序重置；对拍只看单文件 |
| 标准库方法表过大 | 只登记教程与自举源码实际用到的签名，其余保持诊断 |
| 记录/密封合成成员顺序 | 以第33–35课 MIR 为准逐项对照 |
| 内部类命名规则差异 | 以第26课参考 MIR 为准 |
| 自举源码触发新形态 | 先补降级，不改参考实现，不写特例绕过 |
| 回归变慢 | 自举对拍只在 `-含原生` 下跑，日常用单文件脚本 |


失败时按中文诊断修，最多 3 轮；3 轮仍失败把诊断原文交回，不猜。

## 7. M11 之后的路线

| 里程碑 | 方向 | 主要内容 | 验收 |
| --- | --- | --- | --- |
| M12 | 性能与内存 | 自研标记-清除 GC、影子栈、基准门槛、`-O2` 调优 | 基准不劣于 M6 记录值；GC 压力用例不崩 |

| M14 | 工具链与生态 | 包管理、交叉编译、增量编译扩展、VSCode 补全增强 | `新建 项目` 全流程 + 依赖解析可用 |

其余都可独立排期。
